## 明确不做（含复活条件）

**这些不是「以后可能做」，是「现在决定不做」。** 每一项都有明确的触发条件。

| 不做 | 理由 | 什么条件下重新考虑 |
|---|---|---|
| ptest（busybox/python3/openssl） | 3–5 人日 + 每次点版本要处理上游红，是持续负担 | 需对外举证「发行版内容经上游测试」时 |
| `--deep` 内容级扫描 | 指纹门禁已覆盖大部分，#109 型污染未复发 | 内容级污染复发一次即启动 |
| arm64 常态化 | 纯元数据仓库，架构特定逻辑极少 | 引入架构特定配方时 |
| 实体硬件验证 | 全部证据来自 QEMU，已写成主动声明 | **永久不做**（本项目不出货） |
| 签名链（防整镜像替换） | 只保护 root hash 完整性，边界已声明 | 需要对外宣称「防整镜像替换」时 |
| VEX 产出 | 非 CRA 意义上的制造商，无法定义务 | 出现真实出货/客户尽调 |
| SBOM 与镜像一致性校验 | 同上，2027-12 才需要 | 同上 |
| 路线一 dm-verity@5.0 | 双实现双维护，且需 UEFI | 出现真实 5.0 出货需求 |
