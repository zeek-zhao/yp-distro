## 约束（比计划更容易忘）

1. **跨 release 的能力不能假设可移植**：dunfell 3.1 与 wrynose 6.0 之间隔了三代
   语法（`S`→`UNPACKDIR`、sysvinit→systemd、`DISTRO_FEATURES_BACKFILL` 移除）。
   任何「在 6.0 上成立」的结论，在 5.0 上要重新验证。
2. **构建顺序固定为 wrynose → scarthgap → kirkstone → dunfell**（四版时期口径；
   现行回归只有 wrynose，此顺序仅在对冻结版本重跑回归时适用）：先在已热的
   sstate 上拿第一份报告，把风险后置。
3. **同一组实验的三个变量必须串行**：#72/#73/#74（内核 / systemd / rootfs 格式）
   互相影响启动耗时，同时改就推不出单项收益。

## 阶段收口动作

1. 该里程碑下开放的 issue 清零；
2. 开一个 PR 合入 `main`（ruleset 与 `branch-guard` 都只认 PR 合并），描述里贴验收结论；
3. 在 `main` 上打 annotated tag `vX.Y.Z`，tagger 必须是 `zeek.zhao <zeek.zhao@foxmail.com>`；
4. 建 Release，关闭里程碑；
5. 更新 `docs/06-process/plan/milestones.md` 的勾选与 `docs/06-process/handover.md` 的「当前位置」。

### 明确不做（2026-11-09 决策）

| 不做 | 理由 | 复活条件 |
|---|---|---|
| ptest | 3–5 人日 + 持续维护上游红 | 需对外举证「内容经上游测试」 |
| `--deep` 内容级扫描 | 指纹门禁已覆盖大部分 | 内容级污染复发一次 |
| arm64 常态化 | 纯元数据仓库，架构特定逻辑极少 | 引入架构特定配方 |
| 实体硬件 | 全部证据来自 QEMU | **永久不做** |
| 签名链 | 只保护 root hash 完整性 | 需宣称「防整镜像替换」 |
| VEX / SBOM 一致性 | 非 CRA 制造商 | 出现真实出货/客户尽调 |

完整清单与复活条件见 [`backlog.md`](backlog.md)。
