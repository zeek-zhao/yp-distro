## 1. 现象

`kas build ...dev.yml:/work/s1-lowconc.yml --target yp-image-dev -c populate_sdk_ext`（日志 `/work/build-esdk.log`）在 6047 个任务全部成功（含 llvm-native 3472 步、clang-native 2282 步、mesa-native、qemu-system-native 全编）后，于最后的 `do_populate_sdk_ext` → `archive_sdk` 步骤失败：

```
NOTE: Executing archive_sdk ...
tar: ./bitbake.sock: socket ignored
Killed
WARNING: exit code 137 from a shell command.
ERROR: yp-image-dev-1.0-r0 do_populate_sdk_ext: ... run.archive_sdk.1090705 failed with exit code 137
Tasks Summary: Attempted 6047 tasks of which 4631 didn't need to be rerun and 1 failed.
BUILD_RC=2
```

产物：`.tar.xz` 为 0 字节（归档未完成），但 `sdk-ext/image/`（3.0G）完整存在，含 `environment-setup-x86-64-v3-poky-linux` 与 `layers/openembedded-core/scripts/devtool`。

## 2. 根因（先记录后修）

| # | 事实 | 证据 |
|---|---|---|
| R1 | 归档用 `xz --memlimit=50% --threads=32 -9` 压缩 3G SDK | `run.archive_sdk.*`：`tar cf - . \| xz --memlimit=50% --threads=32 -9 > ...tar.xz` |
| R2 | 该 xz 参数在嵌套沙箱触发 OOM（宿主 shell cgroup memory.max=8G） | `Killed` + `exit code 137`（SIGKILL）；与本 Stage 前段 6/-j2 编译无 OOM 形成对照——瓶颈在归档的 32-thread xz |
| R3 | oe-core 提供可调压缩变量 | `populate_sdk_base.bbclass:90` `SDK_XZ_COMPRESSION_LEVEL ?= "-9"`、`:91` `SDK_XZ_OPTIONS ?= "${XZ_DEFAULTS} ${SDK_XZ_COMPRESSION_LEVEL}"` |
| R4 | 3 小时编译产物完整、只差归档 | `sdk-ext/image` 3.0G 含 environment-setup 与 devtool；tar.xz 0 字节 |

## 3. 修复决策

**采取最小、范围内的修法**：不动配方、不动 base.yml，用本地 kas overlay（`/work/s2-lowxz.yml`，不入库）覆盖 `SDK_XZ_COMPRESSION_LEVEL = "-0"`（最快、内存最低），并限制 xz 线程数，然后**只重跑 `do_populate_sdk_ext`**（6046 个任务已在 sstate，仅归档步骤重跑）。

- 不改 dev/prod 的 DISTRO_FEATURES（不套 ci.yml 的 CHG-004 图形裁剪）——图形链进 eSDK 工具链属 dev edition 既有口径，S1 已记录，不在本 Stage 变更；耗时与现象如实记 RV。
- 压缩级别从 -9 降到 -0 只影响归档体积/速度，不影响 SDK 内容正确性；devtool 可用性在解压后的环境验证。
- 若 `-0` 仍 OOM，进一步降 `XZ_DEFAULTS` 线程或直接 `XZ_OPT` 单线程；不写「已通过」。

## 4. 第二个障碍：devtool-smoke 流程 add/modify 互斥（已修）

归档修复后 `install-sdk.sh` 成功（`SDK_INSTALL_OK`），但 `devtool-smoke.sh` 首跑失败：

```
devtool add yp-smoke-hello  → 成功（do_compile/do_package 完成）
devtool build yp-smoke-hello → 成功
devtool modify yp-smoke-hello → ERROR: recipe yp-smoke-hello is already in your workspace
DEVTOOL_SMOKE_FAIL (rc=1)
```

**根因**：`devtool add` 与 `devtool modify` 是把 recipe 纳入 workspace 的两种互斥入口；add 之后该 recipe 已在 workspace，不能再 modify 同一 recipe。

**修复**：smoke 流程改为 add → build → `devtool reset -n`（清 workspace）→ `devtool modify <现成 recipe m4>` → build → reset。实测 `devtool modify m4` rc=0（m4 在 oe-core 主 meta，SDK 内确定存在）。脚本加 `--modify-recipe` 参数（默认 `m4`）。这是脚本逻辑 bug，非配置/环境问题，不改配方/kas。

## 5. 复验

见 RV-M1-S2 §3：重跑归档后的 installer 产物、`SDK_INSTALL_OK`、devtool smoke（add/modify/build）真实输出。若仍失败，继续在本单记录，不写「已通过」。
