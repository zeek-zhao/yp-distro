## 1. 设计探测期发现（QEMU 启动参数）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| P1 | `root=/dev/sda` → `VFS: Cannot open root device "/dev/sda"`，内核 panic | virtio-blk 设备实测枚举为 `/dev/vda` | 脚本固定 `root=/dev/vda`，并留 `--root` 覆盖口（DES-001 F3） |
| P2 | 默认 `qemu64` CPU → `traps: init[1] trap invalid opcode ... vzeroupper`，`Attempted to kill init` panic | 内核/glibc 用宿主指令集编译含 AVX，qemu64 无 AVX | 用 `-cpu max`（TCG 下传递扩展）；`-cpu host` 在 TCG 下报 `requires KVM or HVF`，禁用（DES-001 F4） |

## 2. 实现期脚本 bug

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| P3 | 首次 `qemu-run.sh` 报 `BOOT_FAIL reason=ext4 /boot 未找到 bzImage-<ver>` | 提取内核的 awk 用 `$5 ~ /^bzImage-[0-9]/`，但 `$5` 是 inode 号，文件名在 `$NF` | 改 `$NF ~ /^bzImage-[0-9]/`，实测提取出 `bzImage-6.18.52-yocto-standard` 并成功启动 |
| P4 | `qemu-smoke.sh` 报 `missing qemu-run.sh: scripts/scripts/dev/qemu-run.sh` | `ROOT=$(dirname $BASH_SOURCE/..)` 得 `scripts/`，再拼 `scripts/dev/...` 重复 | 改为 `RUN="$(dirname $BASH_SOURCE)/qemu-run.sh"`，实测 smoke 正向/负向均正确 |

## 3. 环境事实（非 bug，如实记录）

- 宿主无 `/dev/kvm` → 全程 TCG，RV 明确不写硬件加速通过（AI-001 §2.1 硬要求）。
- 沙箱为嵌套容器且不在自身可见 docker daemon 中 → `docker inspect <hostname>` 失败；脚本诚实标 `docker_inspect=N/A(host-is-nested-container)`，不伪造 `0/0/0`。QEMU 在宿主进程运行、未经过任何限制容器，R4「容器不加限制」对本 Stage 以「未用限制容器跑 QEMU」满足。
- ext4 `/boot/bzImage` 是符号链接，debugfs 无法直接 dump 符号链接名，须取 `bzImage-<ver>` 实体文件（脚本已处理）。
