## 0. 机器与资源分配（用户诉求）

用户要求「分配 128G/32 核机器开发、全部性能给 Docker」。核验结果：

| 维度 | 实测 | 证据 |
|---|---|---|
| 宿主机 CPU | 32 核 | `nproc` = 32 |
| 宿主机内存 | 129308484 kB ≈ 123.3 GiB | `/proc/meminfo MemTotal` |
| Docker daemon 可见 | NCPU=32 / MemTotal=132411887616 B ≈ 123.3 GiB | `docker info --format 'NCPU={{.NCPU}} MemTotal={{.MemTotal}}'` |
| 构建容器资源上限 | `NanoCpus=0`、`Memory=0`、`CpuQuota=0` | `docker inspect yp-m0-build-32c` —— **无限制，即容器可用 Docker 全部 32 核/128 GiB** |
| 容器内可见 | nproc=32 / MemTotal=129308484 kB | `docker exec yp-m0-build-32c bash -c 'nproc; grep MemTotal /proc/meminfo'` |

说明：宿主 shell 进程自身被 cgroup 限到 4 核/8 GB（`cpu.max=400000/100000`、`memory.max=8589934592`），但 **Docker daemon 及其容器不受此限**—— daemon 见 32 核/132 GB，容器未加 `--cpus`/`--memory`，因此构建全程独占全部性能。这正满足「全部性能给 Docker」。

## 1. 构建前置

- 镜像：`ghcr.io/zeek-zhao/yp-builder:wrynose-m0`（路径 A，jenkins/1000，卷属主 1000:1000 匹配）。
- 卷：E1 真实全量重下的 `/workspace/m01-e1/downloads`（1288 文件）与 `sstate`（6945 文件），owner `ubuntu:ubuntu`(1000:1000)。
- 容器：`docker run -d --name yp-m0-build-32c -v $PWD:/mnt/repo:ro -v /workspace/m01-e1/downloads:/work/downloads -v /workspace/m01-e1/sstate:/work/sstate <image> sleep infinity`，**未加任何 CPU/内存限制**。
- 工作副本：`tar` 复制仓库（排除 `.git`/`downloads`/`sstate`/`cache-work`）到容器内 `/work/build-run`。
- 构建命令：`kas build kas/yp.yml:editions/prod.yml`（prod edition，`IMAGE_FSTYPES=ext4`）。
