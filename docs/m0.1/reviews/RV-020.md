## 1. T1 · 并发资源化证据

### 1.1 threads.sh 分级（R1）

`bash scripts/build/threads.sh`（宿主，Docker daemon 32c/123GiB）：

```
RESOURCE_TIER=standard
RESOURCE_CORES=32
RESOURCE_MEM_GB=123
export YP_BUILD_THREADS=32
export YP_PARALLEL_MAKE='-j 16'
```

显式覆盖 `YP_BUILD_THREADS=4 YP_PARALLEL_MAKE='-j 2' bash scripts/build/threads.sh` → 输出 4/-j2（tier 仍按 daemon=standard，覆盖仅改 export）。非法覆盖（`YP_BUILD_THREADS=0`、`-j x`）均 exit 1。

### 1.2 bitbake 真生效（R3）——含 ISS-037 修复

**问题**：按提示词 §2.2 写 `${@os.environ.get('YP_BUILD_THREADS','4')}` + 容器注入 32，`bitbake-getvar` 恒返回 4/-j2。穷举验证（env 段默认 4/32/null、`?=`/`??=`+`${VAR}`、docker exec -e、`kas -E`、extra args）均无效；`kas shell -c python3` 内 `os.environ.get`=None 而 shell `$YP_BUILD_THREADS`=32 → 根因是 kas 5.5 隔离 bitbake server 的 os.environ（详见 ISS-037）。

**修复**：改用 bitbake 原生 `${@oe.utils.cpu_count()}` / `-j ${@...//2}`。杀掉旧 bitbake server 后 fresh `bitbake-getvar`（构建容器内，同一 build 目录）：

```
LIVE_T=[32]
LIVE_P=[-j 16]
```

→ R3 通过：bitbake datastore 实际 `BB_NUMBER_THREADS=32`、`PARALLEL_MAKE=-j 16`。
