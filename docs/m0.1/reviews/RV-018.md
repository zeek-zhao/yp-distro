## 3. E3 · `--mode ghcr` 全链路 + K-8

**3.1 事前核验**：两片 registry digest 经 GHCR API (`docker-content-digest`) 独立核对与 manifest 一致（`f1404012…`/`899af6fa…`）。

**3.2 K-8 改造（`scripts/cache/fetch-cache.sh`，CHG-020）**：check_target 前置到 pull 循环前、按 digest 拉取、RepoDigests 校验、缺 digest 回退记 `DIGEST_FALLBACK`。
- 非空目标快速失败测试：预置 `downloads/keepme` → `ERROR: 目标 ... 含非 marker 条目`，rc=1，`ELAPSED=0s`，日志无 `PULL_OK`（拉取前拒绝，K-8 核心）。
- DIGEST_FALLBACK dry-run：构造无 digest manifest → `pull_ref=tag DIGEST_FALLBACK=1`（两片）；有 digest → `pull_ref=digest`。

**3.3 首跑暴露两个真实缺陷（先开单 ISS-036）**：
1. manifest 分片 01 的 `sha256` 字段为 63 字符截断值（末尾缺 `c`），`SLICE_OK` 比对失败（bytes 一致却 sha256 不符）。从 GHCR 镜像实际提取 `cache.slice.01`：`sha256=fbe9e356…d54c`（64 字符）= manifest 字段 + `c`。→ 修复字段（CHG-020）。
2. 修复 sha256 后 `MERGE_OK sha256=a8870b50…` 通过，但解包报 `未知归档布局（顶层项: yp-dl.tar yp-st.tar）`。独立确认源 tar（`a8870b50…`）布局：`yp-dl.tar`+`yp-st.tar`，内层 `yp-dl/`（1288 文件含 `.yp-volume`）、`yp-st/`（6945 文件含 `.yp-volume`）。→ `unpack_archive` 新增 `two-stage-yp` 分支归一为 downloads/sstate（CHG-020），manifest `layout=UNVERIFIED`→`two-stage-yp`。

**3.4 修复后完整重跑（CHG-020 后）**：
```bash
bash scripts/cache/fetch-cache.sh --mode ghcr --manifest manifests/full-slices-manifest.json \
  --dest-parent /workspace/m01-e3-ghcr3 --work /workspace/m01-e3-ghcr3-work
```
真实输出（`/workspace/m01-e3-ghcr3.log`）：
```text
DIGEST_OK index=00 manifest_digest=sha256:f1404012... repo_digest_match=yes
SLICE_OK index=00 bytes=8589934592 sha256=292d3d69...
DIGEST_OK index=01 manifest_digest=sha256:899af6fa... repo_digest_match=yes
SLICE_OK index=01 bytes=2563463168 sha256=fbe9e356...d54c
MERGE_OK out=.../merged.tar bytes=11153397760 sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc source_sha256=a8870b50...
STRUCT_OK mode=two-stage-yp downloads=1288 sstate=6945
UNPACK_OK dest_parent=/workspace/m01-e3-ghcr3 mode=two-stage-yp
FETCH_OK mode=ghcr   ELAPSED=173s
```
卷属主 `ubuntu:ubuntu`（1000:1000），文件数 dl=1288 / st=6945。

结论：E3 通过。GHCR 源 tar 布局由 `UNVERIFIED` 确认为 `two-stage-yp`（`yp-dl.tar`+`yp-st.tar`），此前 M0 各轮均标 UNVERIFIED，本轮首次真实拉取验证。manifest `total_bytes`/分片 `bytes`/`digest`/`source_sha256` 未改；分片 01 `sha256` 由 63→64 位补 `c`（笔误修复，ISS-036）。
