## 2. T1 · 修 `scripts/ai-entry.sh`

### 2.1 状态判定

把“完成”判定改为前缀/包含语义，至少覆盖：

- `完成`
- `完成（Stage E 接线 + 契约收紧）`
- `完成 / 端到端已验`
- `完成（…）`

建议：

```awk
done = (state ~ /^完成/ || state ~ /^已验/)
if (!done) { ... }
```

不要用精确相等；不要把 `未完成` 误判为完成。

### 2.2 `--next` 无后续 Step 的分支

当 `next_row` 为空时：

- 不执行 `read` 到空变量后继续打印 “Step （）”；
- 输出：`M0 全部 Step 已完成；M0.1 已闭环；M1 未立项，先补 M1 范围/PRD 评审，不直接写 M1 代码。`
- 退出码 `0`。

### 2.3 正常输出

全部 Step 完成后，普通模式也应输出：

```text
下一步   : M0/M0.1 已闭环；M1 未立项（需 PRD/范围评审）
取提示词 : 先写 M1 范围，再拉 feat-m1-*
```

不要保留“下一步 S6”的误报。

### 2.4 可测试性

为了验证不同状态，允许 `PLAN` 路径支持环境变量覆盖，例如：

```bash
PLAN="${PLAN_OVERRIDE:-$ROOT/docs/m0/plan.md}"
```

用临时 plan 文件测试：

- 有 `完成（…）`、`完成 / …` 的状态应跳过；
- 遇到 `进行中` 应停止并选择该 Step；
- 全部完成时 `--next` 不应输出“实现 Step ”。

这是入口脚本的可测试性改造，不得改变正常路径的输出语义。
