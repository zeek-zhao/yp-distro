# YP-M0-ISS-009 · meta-yp-distro 层依赖名与 meta-poky 的 collection 名不一致

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-009 |
| 状态 | Closed（已修复；构建推进过 layer 依赖校验阶段） |
| 严重度 | 高（阻断 S5 实际构建） |
| 发现阶段 | Stage D 第二次 `kas build` 尝试（ISS-008 修复后） |
| 关联 | DES-001（层骨架）、DES-005、ISS-008 |
| 发现人 / 日期 | zeek.zhao / 2026-11-25 |

## 1. 现象

ISS-008 修复后重跑构建，`bblayers.conf` 中已包含 `${TOPDIR}/../meta-yocto/meta-poky`，但 bitbake 仍报：

```text
ERROR: Layer 'meta-yp-distro' depends on layer 'meta-poky', but this layer is not enabled in your configuration
BUILD_DONE label=first wall_seconds=2 rc=2
BUILD_DONE label=second wall_seconds=2 rc=2
=== ARTIFACTS ===
NO_IMAGE_DIR
```

## 2. 根因

`meta-yp-distro/conf/layer.conf` 写的是：

```bitbake
LAYERDEPENDS_meta-yp-distro = "core meta-poky"
```

但容器内 `meta-yocto/meta-poky/conf/layer.conf` 实际注册的是：

```bitbake
BBFILE_COLLECTIONS += "yocto"
```

bitbake 的 `LAYERDEPENDS` 校验按 **collection 名**匹配，目录名 `meta-poky` 不等于 collection 名 `yocto`，因此判定依赖未启用。S1 设计时按目录名写依赖，未核对上游 layer.conf 的实际 collection 名；`kas dump` 与静态检查都不校验 LAYERDEPENDS，所以 Stage B 未发现。

## 3. 修复

把依赖名从目录名改为真实 collection 名：

```bitbake
LAYERDEPENDS_meta-yp-distro = "core yocto"
```

其余层依赖不变（`core` 对应 openembedded-core/meta，`yocto` 对应 meta-poky）。

## 4. 验证证据

修复为 `LAYERDEPENDS_meta-yp-distro = "core yocto"` 后重跑：

```text
Parsing of 2002 .bb files complete (0 cached, 2002 parsed). 3526 targets, 104 skipped, 0 masked, 0 errors.
Build Configuration:
  MACHINE = "qemux86-64"    DISTRO = "yp-wrynose"
  meta-poky = "HEAD:7c25b111..."    meta-oe = "HEAD:c0fcd7cc..."
NOTE: Resolving any missing task queue dependencies
NOTE: Running task 1 of 4630 ...
```

`Layer 'meta-yp-distro' depends on layer 'meta-poky' ... not enabled` 错误消失，构建推进到 4630 任务队列执行阶段，证明本问题已关闭。后续中断为独立的环境类问题（ISS-010）。

## 5. 关闭

- 关闭条件：`LAYERDEPENDS` 校验通过、构建推进过 layer 依赖检查并进入任务执行——**达成**。
- 关闭人 / 日期：zeek.zhao / 2026-11-25
- **下次如何避免**：写 `LAYERDEPENDS` 必须核对上游 `layer.conf` 的 `BBFILE_COLLECTIONS` 实际值（目录名 ≠ collection 名，meta-poky 的 collection 叫 `yocto`），不能按目录名推断；S1 骨架阶段就应把 collection 名写入设计文档，并在首次构建冒烟时校验。
