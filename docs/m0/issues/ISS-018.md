# YP-M0-ISS-018 · sstate 文件名含冒号导致 upload-artifact 拒绝

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-018 |
| 状态 | Closed（2026-11-25，run 45607197090 验证通过） |
| 发现时间 | 2026-11-25 |
| 作者 | zeek.zhao |
| 关联 | CHG-011、ISS-017、判据 7 |
| 严重度 | 中（prepare job 在制品上传阶段失败） |

## 1. 现象（只写观察到的事实）

- 修复 ISS-017 后重跑发布 run `45606884016`（HEAD `9ed1f7f`）：`publish-builder`/`publish-cache` success，`prepare-cache-payload` 在下载解包成功后、`actions/upload-artifact@v4` 阶段失败，`publish-cache-slices` skipped。
- prepare job 先打印 `S5_PAYLOAD_SAMPLE_OK files=15`，随后日志：

```text
With the provided path, there will be 15 files uploaded
##[error]The path for one of the files in artifact is not valid: /sstate/sstate:libgcrypt-native:x86_64-linux:1.12.1:...tar.zst. Contains the following character:  Colon :
Invalid characters include:  Double quote ", Colon :, Less than <, Greater than >, Vertical bar |, Asterisk *, Question mark ?, Carriage return \r, Line feed \n
```

- 原始 S5 文件名来自 real sstate 对象：`sstate:<recipe>:<arch>:<version>:<rev>:<arch>:<hash>_<task>.tar.zst`，天然含多个 `:`。

## 2. 复现

```bash
export GH_TOKEN='<PAT>'
curl -sSL -H "Authorization: Bearer $GH_TOKEN" \
  'https://api.github.com/repos/zeek-zhao/yp-distro/actions/jobs/139179949000/logs' \
  | grep -n 'S5_PAYLOAD_SAMPLE_OK\|Colon :'
```

- 期望结果：15 个文件作为 `cache-payload` 制品上传成功，下游 pack/split/publish 继续。
- 实际结果：上传被 artifact 文件名规则拒绝，job 红。
- 首次出现于：run `45606884016` / 提交 `9ed1f7f`。

## 3. 根因分析

- 直接原因：`actions/upload-artifact@v4` 禁止文件名含 `:`（NTFS 兼容规则），而 Yocto sstate 文件名按设计含 `:`。
- 本地模拟只验证了 tar 解包与目录非空，没有验证 artifact 上传的文件名规则。
- 排除过的假设：不是载荷缺失（15 个文件已解包）；不是权限（其余两个 job push GHCR 成功）；不是表达式（ISS-017 已修，输出正常）。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施 | 不填 digest，发布端到端继续 UNVERIFIED | zeek.zhao | 已执行 |
| 永久措施 | prepare job 在上传前把文件名中的 `:` 替换为 `_`，并断言无残留非法字符 | zeek.zhao | 本次修复 |

- 说明：只改制品传输用的文件名，不改文件内容，也不改 pack/split/merge 逻辑；原始 sstate 语义由 siginfo 文件名一并保留（同样替换冒号）。

FILES=15 COLONS=0          # find /tmp/s5-payload -type f -name '*:*' → 0

139181038430 prepare-cache-payload completed success
139181038752 publish-cache completed success

139181159255 publish-cache-slices completed success
docker-content-digest: sha256:11ae257dd1049ab25667538fbcc79d5b342777f401c608718c5da7c35062088a

- 结论：通过——上传前文件名清理后无冒号，15 个文件全部上传，下游切分与发布成功，digest 由 GHCR 独立核验。

## 6. 关闭

- 关闭条件：已满足——run `45607197090` 四 job 全 success，`publish-cache-slices` 产出真实 digest 并经 GHCR registry API 独立核验。
- 关闭人 / 日期：zeek.zhao / 2026-11-25。
- **下次如何避免**：制品上传前用 `find -name '*:*'` 等规则做预检；本地模拟要覆盖 upload-artifact 的文件名约束，而不只是文件存在性。
