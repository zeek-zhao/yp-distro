## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：
  - 以 uid=1234 普通用户执行默认 `bootstrap.sh`（不带 `--uid`）→ `ERROR[2] UID_MISMATCH`，符合契约；属主目标仍是 1000。
  - 但 runbook §5.2 路径 B、`m0-new-machine-test-prompt.md` §4.2 路径 B 给出的 `bootstrap.sh` / `preflight.sh` **不带** `--uid/--gid`，照抄会因默认目标 1000 与当前 UID 1234 不一致而 exit 2，路径 B 实际不可执行。
  - runbook §3 步骤 7 的 `docker run` 把 GHCR 镜像 `ghcr.io/zeek-zhao/yp-builder:wrynose-m0` 写死，路径 B 重建的 `yp-builder:local`（uid=1234）不会被使用，卷 1234 配上容器 1000 → entrypoint 拒绝。
- 影响范围：所有 UID≠1000 且选择路径 B（本地重建镜像）的新机；路径 A 的 sudo 命令已正确。

## 2. 复现

```bash
# /tmp 隔离探针，uid=1234
rm -rf /tmp/uid6 && mkdir -p /tmp/uid6 && chown -R 1234:1234 /tmp/uid6
runuser -u uid1234 -- bash scripts/bootstrap.sh --downloads /tmp/uid6/dl --sstate /tmp/uid6/sstate --min-free-bytes 0
echo "DEFAULT_BOOT_RC=$?"          # 2，打印 UID_MISMATCH
runuser -u uid1234 -- bash scripts/bootstrap.sh --downloads /tmp/uid6/dl --sstate /tmp/uid6/sstate --min-free-bytes 0 --uid 1234 --gid 1234
echo "EXPLICIT_BOOT_RC=$?"         # 0
runuser -u uid1234 -- bash scripts/preflight.sh --downloads /tmp/uid6/dl --sstate /tmp/uid6/sstate --min-free-bytes 0 --uid 1234 --gid 1234
echo "EXPLICIT_PF_RC=$?"           # 0
```

- 期望结果：路径 B 文档命令应带 `--uid "$(id -u)" --gid "$(id -g)"` 且 `docker run` 用 `$YP_BUILDER_IMAGE`。
- 实际结果：文档路径 B 命令不带 UID 参数（runbook §5.2、test prompt §4.2），步骤 7 写死 GHCR 镜像。
- 首次出现于：提交 `35c4119`（CHG-017 收口后文档仍保留原路径 B 写法）。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：CHG-014 把脚本默认目标 UID 从「当前用户」改为镜像用户 1000 后，只更新了路径 A 的 sudo 命令与 §4.2 默认路径说明，未同步更新路径 B 的 bootstrap/preflight 示例。
- 根本原因：路径 B 需要「显式当前 UID + 本地镜像变量」两个条件同时成立，文档只写了重建镜像与 `export YP_BUILDER_IMAGE`，漏了脚本的显式 UID 参数与 `docker run` 的变量引用。
- 排除过的假设及排除依据：脚本逻辑本身正确（显式 `--uid 1234` 探针 exit 0、属主 1234），问题在文档命令，不在脚本。
