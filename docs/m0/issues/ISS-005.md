# YP-M0-ISS-005 · 孤立分支的 workflow 无法被 GitHub Actions 识别与 dispatch

## 1. 现象（只写观察到的事实）

- `gh workflow run m0.yml --ref feat-m0-kas-bootstrap` → `HTTP 404: workflow m0.yml not found on the default branch`。
- `POST /repos/zeek-zhao/yp-distro/actions/workflows/m0.yml/dispatches` with `ref=feat-m0-kas-bootstrap` → `404 Not Found`。
- `GET /actions/workflows` 仅返回 `ci`、`images`、`pull-check`（均在 main），无 `m0.yml`。
- 影响范围：S7「Actions 自动发布」无法在孤立分支上触发；不影响本地构建与推送。

## 2. 复现

```bash
gh workflow list --all                                  # ci / images / pull-check
gh workflow run m0.yml --ref feat-m0-kas-bootstrap      # HTTP 404
curl -X POST .../actions/workflows/m0.yml/dispatches -d '{"ref":"feat-m0-kas-bootstrap"}'  # 404
```

- 期望结果：m0.yml 可被 dispatch 触发。
- 实际结果：GitHub 只注册默认分支（main）上的 workflow，孤立分支的 workflow 文件不被识别。
- 首次出现于：提交 `43b14d3`（引入 m0.yml）/ 分支 `feat-m0-kas-bootstrap`。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：GitHub Actions 的 workflow 发现机制只扫描默认分支；`workflow_dispatch` 的 API 入口也只接受默认分支上的 workflow 文件。
- 根本原因：方案 A 的「孤立分支 + 不向 main 开 PR」与「Actions 自动发布」互斥——前者要求 workflow 只在 feat 分支，后者要求 workflow 在 main。这是方案 A 的第二处内在冲突（第一处见 ISS-002）。
- 排除过的假设：非 token 权限问题（用户 PAT 可触发 main 上的 workflow 列表读取）；非语法错误（YAML 本地解析通过）。
- **附加发现（可见性）**：用独立 TOKEN 本地 `docker push` 成功，但两个包 `yp-builder`/`yp-cache` 默认 **private**；匿名 `docker pull` 返回 `unauthorized`。查 GitHub OpenAPI 规范（`api.github.com.json`）确认：**不存在任何修改容器包可见性的 REST/GraphQL 端点**；GHCR 包可见性只能经网页 UI 修改，而 GitHub 网页不支持 PAT 登录（2021 起移除密码认证）。因此 PAT 本地推送路径无法得到公共可拉取的包。
- **关键依据**：用 Actions 内置 `GITHUB_TOKEN` 推送的容器包会自动链接到 workflow 所在仓库并继承仓库可见性（public 仓库 → public 包），这正是方案二能实现匿名拉取的原因；但该路径要求 workflow 位于默认分支。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施（止痛） | 用用户提供的独立 TOKEN（`write:packages`）在本地构建并推送 builder 与 cache 镜像到 GHCR；两个包推送成功（digest 见第 5 节），但为 private，匿名拉取不可用 | zeek.zhao | 2026-11-24 |
| 永久措施（治因，待决策） | 三选一：A) 把 m0.yml 提交到默认分支 main（仅此 workflow 文件，不改其它），用 GITHUB_TOKEN 自动发布使包 public——最接近「方案二」但触碰 main；B) 在 GitHub 网页手动把 yp-builder/yp-cache 包改为 Public（需人类登录网页），随后匿名拉取即可；C) 维持孤立分支 + private 包，放弃匿名拉取，改用 save/load 分发 | 人类/维护者 | 待决策 |

- 后续项：Actions 自动发布与匿名拉取路径均标 UNVERIFIED，待人类决策 A/B/C 后闭环。

## 5. 验证证据（Verifying 阶段填写）

```bash
# 本地 TOKEN 发布（临时措施，2026-11-24 执行）
echo "$ALT_TOKEN" | docker login ghcr.io -u zeek-zhao --password-stdin
docker tag yp-builder:wrynose-m0 ghcr.io/zeek-zhao/yp-builder:wrynose-m0
docker push ghcr.io/zeek-zhao/yp-builder:wrynose-m0
docker build -f docker/cache.Dockerfile -t ghcr.io/zeek-zhao/yp-cache:wrynose-m0 docker/
docker push ghcr.io/zeek-zhao/yp-cache:wrynose-m0
```

- 结论：部分通过。真实输出（2026-11-24）：
  - `docker login ghcr.io`（独立 TOKEN）→ Login Succeeded；
  - `docker push ghcr.io/zeek-zhao/yp-builder:wrynose-m0` → `wrynose-m0: digest: sha256:ef28c044b916dea208d4b8d76032d74161d00c681402dd67a82e322eeaea1aa9`；
  - `docker push ghcr.io/zeek-zhao/yp-cache:wrynose-m0` → `wrynose-m0: digest: sha256:0deba6172fa8916f76eabe8424ad0efb22f633d17f7b23ef731d5be9c85a6521`；
  - `docker logout ghcr.io` 后匿名 `docker pull` 两镜像 → `unauthorized`；包可见性查询 → `yp-builder private`、`yp-cache private`。
  - Actions 自动发布与匿名拉取：UNVERIFIED（ISS-005 决策待定）。

## 6. 关闭

- 关闭条件：镜像成功推送且公共匿名拉取可用；Actions 自动发布路径按决策处理。
- 关闭人 / 日期：待定
- **下次如何避免**：设计 CI 前先确认 workflow 所在分支是否为默认分支；孤立分支上的 workflow 不会被 Actions 注册，需在 ADR 中一并裁决分支策略与 CI 策略。
