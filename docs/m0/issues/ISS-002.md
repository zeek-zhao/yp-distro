## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：`gh pr create --draft --base main --head feat-m0-kas-bootstrap` 返回
  `GraphQL: The feat-m0-kas-bootstrap branch has no history in common with main (createPullRequest)`。
- 影响范围：m0-prompt 第六节第 4 条「S0 后开 draft PR」无法实现；S1 提交已在远程分支（push 成功），但无法进入 PR 评审流程。

## 2. 复现

```bash
cd /workspace/yp-distro
git merge-base origin/main HEAD            # 无输出（退出非 0）：无共同祖先
git rev-list --max-parents=0 origin/main   # 16a9122d...
git rev-list --max-parents=0 HEAD          # ee5377d...（不同根）
gh pr create --draft --base main --head feat-m0-kas-bootstrap --title "..." --body "..."
# 实际结果：GraphQL 错误，无共同历史
```

- 期望结果：draft PR 创建成功，CI 触发。
- 实际结果：GitHub 拒绝创建 PR。
- 首次出现于：提交 `d3e8f8a`（首次尝试 PR）/ 分支策略在 S0 `ee5377d` 即已埋下。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：GitHub 的 PR 机制要求 base 与 head 至少有一个共同提交；本分支按 m0-prompt 第六节第 1 条刻意做成孤立分支（与 main 无共享历史）。
- 根本原因：规范内部冲突——第六条同时要求「孤立分支，与 main 无共享历史」与「S0 后向 main 开 draft PR」，二者在 GitHub 上互斥。这不是执行错误，是工作流约定需要人类裁决。
- 排除过的假设：
  - 非 token 权限问题——push 已成功，token 具备 repo 权限；
  - 非分支名问题——远程分支 `origin/feat-m0-kas-bootstrap` 存在且已更新到 `d3e8f8a`；
  - 非 base 选错——仓库只有 `main` 一个可合并基线。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施（止痛） | 保持分支现状，提交与 push 正常进行；评审改用 commit diff / 分支对比，不强行造 PR | zeek.zhao | 已执行（S1 已 push） |
| 永久措施（治因，待决策） | 二选一，须人类批准：A) 维持孤立分支，修订 m0-prompt 工作流为「不用 PR，用 commit + 评审记录」；B) 放弃孤立分支，从 main 切出重放提交，按 CHG/ADR 变更分支策略 | 人类批准人 | 待决策 |

- 只做了临时措施，后续项编号：需人类在 A/B 间决策；决策前 M0 不声称「PR 工作流已就绪」。
