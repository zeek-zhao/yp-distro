# YP-M0-ISS-039 · runbook/测试提示词把 env export 当 bitbake 并发控制通道（实为 no-op）

| 项 | 值 |
|---|---|
| 文档编号 | YP-M0-ISS-039 |
| 状态 | Resolved（删除 eval/export，threads.sh 改只读 SUGGEST_* 诊断，bitbake-getvar 为唯一验收） |
| 提出日期 | 2026-11-27 |
| 关联 | YP-M0-CHG-022 / YP-M0-ISS-037 / YP-M0.1-RV-021；AI-010 §2.2/§2.3/§3.1/§3.2；分支 `feat-m0.1.2-resource-fallback` |
| 严重度 | P3（误导性文档：照做不会改变 bitbake 并发，但不破坏构建） |

## 1. 现象

M0.1.1 的 `docs/runbook-new-machine.md` 步骤 7 与 `docs/ai/m0-new-machine-test-prompt.md` 构建段写：

```bash
eval "$(bash scripts/build/threads.sh)"
export YP_BUILD_THREADS YP_PARALLEL_MAKE
# 注释：eval 输出可直接设置导出变量，容器继承后注入 bitbake
```

`threads.sh` 当时输出两行 `export YP_BUILD_THREADS=...` / `export YP_PARALLEL_MAKE='...'`，eval 后在宿主 shell 得到这两个环境变量，runbook 声称“容器继承后注入 bitbake”。

**实际是 no-op**：ISS-037 已实测 kas 5.5 隔离 bitbake server 的 `os.environ`，自定义变量不进 datastore；宿主 export 的两个变量不会改变 `BB_NUMBER_THREADS` / `PARALLEL_MAKE`。ISS-037 当时改用 `oe.utils.cpu_count()` 绕开 env，但没有把这两处失效的 eval/export 接线删掉，形成“文档说的控制通道实际无效”的误导。

## 2. 复现（grep 前后证据）

修复前（AI-010 §1 复现）：

```text
docs/runbook-new-machine.md:160:eval "$(bash scripts/build/threads.sh)"
docs/runbook-new-machine.md:161:export YP_BUILD_THREADS YP_PARALLEL_MAKE
docs/ai/m0-new-machine-test-prompt.md:224:eval "$(bash scripts/build/threads.sh)"
docs/ai/m0-new-machine-test-prompt.md:225:export YP_BUILD_THREADS YP_PARALLEL_MAKE
```

修复后（CHG-022）：

```bash
git grep -nE 'eval "\$\(bash scripts/build/threads.sh\)"|export YP_BUILD_THREADS|export YP_PARALLEL_MAKE' \
  -- README.md AGENTS.md docs/runbook-new-machine.md docs/ai/m0-new-machine-test-prompt.md
# -> 无命中（NONE）
```

`threads.sh` 不再输出 `export YP_*`，改输出 `SUGGEST_BUILD_THREADS` / `SUGGEST_PARALLEL_MAKE`（daemon 级诊断）；`verify-env.sh` 改解析 `SUGGEST_*=` 并标注 `DIAGNOSTIC_ONLY`；runbook/测试提示词改为只读诊断 + 容器内 `bitbake-getvar` 验收（唯一实际值来源）。

## 3. 修复要点

| 位置 | 修复前 | 修复后 |
|---|---|---|
| `threads.sh` | 输出 `export YP_*`，含 env 覆盖逻辑 | 只读诊断输出 `SUGGEST_*`，无 export、无 env 覆盖 |
| `verify-env.sh` | 解析 `export YP_*` | 解析 `SUGGEST_*=` 并标注 DAEMON 级诊断、非 bitbake 实际值 |
| runbook 步骤 7 | `eval` + `export` + “容器继承后注入”注释 | `bash threads.sh` 只读诊断 + `bitbake-getvar` 验收 |
| 测试提示词构建段 | 同上 | 同上；明确 `SUGGEST_*` 不作已生效证据 |
| `AGENTS.md` §2.1 | 无 threads.sh 约束 | 补硬约束：threads.sh 非控制通道，不得 eval/export 注入 |

## 4. 影响面

- 照旧 runbook 执行的用户不会再用无效手段“调并发”；改为看 `bitbake-getvar` 真值。
- 历史文件（AI-009 提示词、RV-020、CHG-021）保留原文，只追加“后续更正见 CHG-022 / RV-021”指针，不改写旧结论（AI-010 §3.3）。
- 门禁 G6 与 check-vars 增加负向断言，检出 `export YP_*` / env 控制通道残留，防回归。

## 5. 回滚

恢复 export 会重现误导（且仍无效）；不建议。按 CHG-022 §回滚执行。
