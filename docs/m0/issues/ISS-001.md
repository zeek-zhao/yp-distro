## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：执行 `command -v kas bitbake bitbake-layers` 均为 `NOT_FOUND`；本仓库 S1 尚无 `kas/yp.yml`（属 S2 产出）。
- 影响范围：S1 两条主验收命令（`bitbake-layers show-layers`、`kas dump`）无法在本环境实跑；不影响代码与文档的正确性，但影响「构建成功」类结论的证据等级。

## 2. 复现

```bash
cd /workspace/yp-distro
for t in kas bitbake bitbake-layers; do command -v "$t" || echo "$t NOT_FOUND"; done
# 实际结果：三行均输出 NOT_FOUND
test -e kas/yp.yml && echo exists || echo "kas/yp.yml 不存在（属 S2）"
# 实际结果：不存在
```

- 期望结果：三工具均可用，且 `kas/yp.yml` 存在可 dump。
- 实际结果：三工具缺失；kas 入口文件尚在 S2 范围。
- 首次出现于：提交 `60329ad` / 环境：Ubuntu 22.04 沙箱（预装包清单无 yocto/kas）。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：执行沙箱为轻量构建环境，未安装 Yocto/bitbake/kas 工具链，也没有 wrynose 层的本地 checkout。
- 根本原因：本 Step 的环境假设与 S1 验收命令的运行时依赖不匹配；S1 的 kas dump 验收本身依赖 S2 才产出的 `kas/yp.yml`，Step 表在时序上存在前置耦合。
- 排除过的假设及排除依据：非代码缺陷——静态断言（变量声明、文件存在）全部通过，见第 5 节。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施（止痛） | 用不依赖 bitbake 的静态断言验证层骨架结构（文件、变量、取值唯一性），本步执行 | zeek.zhao | 2026-11-24 |
| 永久措施（治因） | 在 CI（`.github/workflows/m0.yml`，S8 产出）中提供带 kas/bitbake 的完整环境，实跑 `bitbake-layers show-layers` 与 `kas dump`，回填 acceptance.md 证据 | zeek.zhao | S8 |

- 如果只做了临时措施，后续项编号：S8（CI 门禁）承担永久措施；在 S8 完成前，S1 主验收证据保持 `UNVERIFIED`。
