## 1. 现象（只写观察到的事实）

- GitHub Actions run `45594520683`（`event=push`、`head_sha=b072417`、`workflow=.github/workflows/m0-gate.yml`）结论 `failure`；用户提供的失败点为 `scripts/check-vars.sh`：`checked=28 drift=2`，`DRIFT [MACHINE_measure]`、`DRIFT [EDITION_measure]` 均报 `scripts/build/measure.sh` 文件缺失。
- 公开 API 实取：`GET /repos/zeek-zhao/yp-distro/actions/runs/45594520683` → `"event": "push"`、`"head_branch": "feat-m0-kas-bootstrap"`、`"head_sha": "b072417..."`、`"conclusion": "failure"`；`GET .../jobs` → `gate / failure`。日志正文接口返回 `403 Must have admin rights to Repository`，故具体行以用户提供的输出为准。
- 本地工作区 `bash scripts/check-vars.sh` 却输出 `VARS_OK`、`checked=28 drift=0`；两者不一致。
- 干净检出复现（`git archive HEAD | tar -x -C <tmp>` 后运行）得到同样两项漂移：

```text
  DRIFT [MACHINE_measure] 文件缺失: scripts/build/measure.sh
  DRIFT [EDITION_measure] 文件缺失: scripts/build/measure.sh
===== RESULT: checked=28 drift=2 =====
VARS_DRIFT_DETECTED
CLEAN_CHECKOUT_EXIT=1
```

- 影响范围：判据 8 的 CI 证据、S8/S9 门禁结论；不影响已产出的 ext4 镜像与 sstate 缓存载荷（它们在卷上，不在仓库内）。

## 2. 复现

```bash
cd /workspace/yp-distro
git ls-tree -r --name-only HEAD scripts/build        # 无输出：HEAD 未收录 measure.sh
TMP=$(mktemp -d); git archive HEAD | tar -x -C "$TMP"
(cd "$TMP" && bash scripts/check-vars.sh); echo "CLEAN_CHECKOUT_EXIT=$?"
git check-ignore -v scripts/build/measure.sh         # .gitignore:4:build/  scripts/build/measure.sh
```

- 期望结果：干净检出中 `scripts/build/measure.sh` 存在，`check-vars.sh` 输出 `VARS_OK`、`drift=0`。
- 实际结果：干净检出中文件缺失，两项 DRIFT + exit 1。
- 首次出现于：提交 `b072417`（Stage F 引入 variable-index 第 27/28 行与 check-vars 规则）/ CI run `45594520683`。

## 3. 根因分析

- 直接原因：`scripts/build/measure.sh` 只存在于执行方工作区，未进入任何提交，CI checkout 自然取不到。
- 根本原因：`.gitignore` 第 4 行的 `build/` 是无锚点目录模式，匹配任意层级的 `build/` 目录，因此连带忽略 `scripts/build/`；执行方此前用普通 `git add` 无法把该文件入索引，本地检查却因文件仍在磁盘上而误报通过。
- 排除过的假设：不是 `variable-index.md` 第 27/28 行写错（两行与 DES-005 §3.5 的默认 `ci`/`qemux86-64` 一致，且用户明确禁止删行变绿）；不是脚本内容漂移（工作区文件内两行字面值与索引完全一致，`grep -F` 命中）。
