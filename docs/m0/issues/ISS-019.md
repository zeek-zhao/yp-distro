# YP-M0-ISS-019 · 全量 11 GiB 载荷 split→merge sha256 不符

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-019 |
| 状态 | Closed（2026-11-25，split.sh 改按字节 skip/count，全量 11 GiB 回归 MERGE_OK） |
| 发现时间 | 2026-11-25 |
| 作者 | zeek.zhao |
| 关联 | CHG-012、DES-006、DES-008、判据 7 |
| 严重度 | 高（全量载荷无法无损恢复，阻断全量发布验证） |

## 1. 现象（只写观察到的事实）

- 用全量 S5 缓存（`/tmp/yp-dl` + `/tmp/yp-st`，共 11,136,866,732 B）执行与 workflow 相同的脚本链：
  - `PACK_OK out=/tmp/full-chain/full.tar size=11153397760 sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc`
  - `SPLIT_OK slices=2 total_bytes=11153397760 source_sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc max=8589934592`
  - `merge.sh` → `ERROR: 合并结果 sha256 (1feeb539cfeee5d3cad4420dca6907fa3b7c62a9c715f3e61db95dcb081df464) 与源 sha256 (a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc) 不符，拒绝恢复`
- 同一套脚本在 18 MB 样本载荷上 `MERGE_OK`、sha256 一致（run `45607197090` 与本地 T5 均通过）。
- 差异只在载荷体量跨越 `SLICE_MAX_BYTES=8589934592`（8 GiB）产生 2 片时出现。

## 2. 复现

```bash
bash scripts/cache/pack.sh --src /tmp/yp-dl --src /tmp/yp-st --out /tmp/full-chain/full.tar
bash scripts/cache/split.sh --in /tmp/full-chain/full.tar --out /tmp/full-chain/slices
bash scripts/cache/merge.sh --in /tmp/full-chain/slices --out /tmp/full-chain/merged.tar
# 期望 MERGE_OK 且 sha256 一致；实际 exit 1 + sha256 不符
```

## 3. 根因分析

- 事实：源 `full.tar` = 11,153,397,760 B；`SPLIT_OK slices=2` 但两片各只有 **2,147,479,552 B**（= 2^31 − 4096，即 GNU dd 对超大 `bs` 的实际分块上限），合计 4,294,959,104 B，`merged.tar` 也为该值。
- 直接原因：`split.sh` 用 `dd if="$IN" of="..." bs="$MAX" skip="$idx" count=1`。当 `MAX=8589934592`（8 GiB）时，GNU dd 无法分配 8 GiB 的单块，实际按约 2 GiB 分块；`skip=1` 只跳过 ~2 GiB 而非第 2 个 8 GiB 块，导致只覆盖源的前 ~4 GiB，后 ~7 GiB 丢失。`merge.sh` 的 sha256 比对正确检出数据丢失并拒绝恢复（失败即停设计生效）。
- 样本载荷（18 MB < 8 GiB）只产生 1 片，`skip=0`，故从未触发该缺陷；T5 的 4 片测试用的是 `YP_SPLIT_MAX_BYTES=6291456`（6 MiB，远小于 dd 上限），也未触发。
- 排除过的假设：不是 `merge.sh` 拼接顺序错误（两片 sha256 与 manifest 一致且 `cat` 顺序正确）；不是 pack 丢数据（源 sha256 与 manifest 一致）；不是磁盘空间不足（当时 228 GB 可用）。

## 3.1 修复方案

- `split.sh` 改为 `dd if="$IN" of="..." bs=1M iflag=skip_bytes,count_bytes skip=$((idx*MAX)) count="$MAX" status=none`，让 skip/count 按字节解释，不再受 `bs` 实际分块大小影响。
- 增加全量回归：11 GiB 载荷必须产生 2 片且逐片字节数之和 == 源字节数，`merge.sh` 后 sha256 与源一致。

## 5. 验证证据（Verifying 阶段填写）

```text
# 修复前（缺陷证据）
slice.00=2147479552 slice.01=2147479552 merged=4294959104
ERROR: 合并结果 sha256 (1feeb539...) 与源 sha256 (a8870b50...) 不符

# 修复后（bash scripts/cache/split.sh 使用 iflag=skip_bytes,count_bytes）
SPLIT_OK slices=2 total_bytes=11153397760 source_sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc max=8589934592
slice.00=8589934592  sha256=292d3d69b8dbe882d09784af067187da14c7b2711019a0e1f938cc311b347573
slice.01=2563463168  sha256=fbe9e3567a87cc427a5e016b5e5b54c797ff8b2e4b4e6ebcbbe92bb47666d54
MERGE_OK out=/tmp/full-chain/merged.tar bytes=11153397760 sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc source_sha256=a8870b50f2b262d90978a17c6bcdf28794659e1dfd7f500f24ddf097dad4febc
sha256sum full.tar merged.tar 两行完全一致
```

- 结论：通过——修复后两片字节数之和等于源，merge sha256 与源一致；全量分片已发布 GHCR（见 ISS-020）。
