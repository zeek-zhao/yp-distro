# YP-M0-ISS-040 · bitbake ConfHandler 不接受 local.conf 多行 python def，分级函数须放 .bbclass

| 项 | 值 |
|---|---|
| 文档编号 | YP-M0-ISS-040 |
| 状态 | Resolved（函数移入 `meta-yp-distro/classes/yp-concurrency.bbclass`，base.yml 用 INHERIT 引入，实测构建通过） |
| 提出日期 | 2026-11-27 |
| 关联 | YP-M0-CHG-022 / YP-M0-ISS-038 / YP-M0.1-RV-021；AI-010 §2.1；分支 `feat-m0.1.2-resource-fallback` |
| 严重度 | P1（阻断构建：按提示词参考实现把 `def` 写进 base.yml 后 bitbake 解析失败） |

## 1. 现象

按 AI-010 §2.1 参考实现，把 `yp_mem_bytes(d)` / `yp_build_threads(d)` 两个 python 函数直接写进 `kas/base.yml` 的 `base: |` 块（该块被 kas 写入 `build/conf/local.conf`）。标准容器跑 `kas build kas/yp.yml:editions/prod.yml` 失败：

```text
INFO - ERROR: Unable to parse .../bitbake/lib/bb/parse/parse_py/ConfHandler.py
INFO - bb.parse.ParseError: ParseError at build/conf/local.conf:16: unparsed line: 'def yp_mem_bytes(d):'
ERROR - Command "bitbake -c build core-image-minimal" failed with error 1
```

## 2. 根因

bitbake 的 `local.conf`（ConfHandler 解析）只接受变量赋值，不支持多行 python `def` 函数定义；多行 `def` 属于 `.bb` / `.bbclass` 的语法。提示词 §2.1 明示“可调整写法，但语义必须一致”，故按实际 bitbake 行为调整承载位置。

## 3. 修复

- 新建 `meta-yp-distro/classes/yp-concurrency.bbclass`，定义 `yp_mem_bytes(d)` / `yp_build_threads(d)`（语义与提示词参考实现一致：cgroup v2→v1→/proc/meminfo 回退；CPU+内存二维分级；至少 1）。
- `kas/base.yml` 删除函数定义，改为 `INHERIT += "yp-concurrency"` + `BB_NUMBER_THREADS = "${@yp_build_threads(d)}"` + `PARALLEL_MAKE = "-j ${@max(1, int(d.getVar('BB_NUMBER_THREADS')) // 2)}"`。
- `scripts/check-vars.sh` / `scripts/gate.sh` G6 / `docs/m0/variable-index.md` #29 的断言目标从 base.yml 改为 `.bbclass`（函数与 cgroup 路径）+ base.yml（INHERIT 与赋值），防回归。

## 4. 修复前后

| 阶段 | 函数位置 | 构建 |
|---|---|---|
| 修复前 | `kas/base.yml`（→ local.conf） | ParseError: unparsed line 'def yp_mem_bytes(d):' |
| 修复后 | `meta-yp-distro/classes/yp-concurrency.bbclass`（INHERIT 引入） | 通过，bitbake-getvar 得 32/-j16（RV-021 §2） |

## 5. 影响面与取舍

- 偏离提示词“函数在 base.yml”的字面承载位置，但**语义完全一致**且构建真实通过；不改 M0 判据、不移动任何 tag。
- 分级逻辑、`threads.sh` 诊断、文档去误导口径均不变。
- 回滚到 base.yml 内 `def` 会重现 ParseError；不建议。

## 6. 证据

首次失败日志见 RV-021 §2（构建 ParseError）；修复后 fresh `bitbake-getvar`=32/-j16、缓存 prod 构建成功见 RV-021 §2。
