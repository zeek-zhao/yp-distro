# YP-M0-ISS-008 · bitbake 仓库被 kas 误当 layer 导致首次构建失败

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-008 |
| 状态 | Closed（已修复；配置校验通过，构建级证据见 ISS-010） |
| 严重度 | 高（阻断 S5 实际构建，但 dump 阶段不可见） |
| 发现阶段 | Stage D 首次 `kas build` |
| 关联 | DES-002（kas 配置）、DES-005、RV-005、B-12/B-13 |
| 发现人 / 日期 | zeek.zhao / 2026-11-25 |

## 1. 现象

在 builder 容器内对工作副本执行 `kas build kas/yp.yml:kas/editions/ci.yml`，首次与第二次均失败：

```text
2026-11-24 16:39:17 - INFO - ERROR: Unable to parse /work/build-run/bitbake/lib/bb/parse/__init__.py
FileNotFoundError: [Errno 2] file /work/build-run/build/../bitbake/conf/layer.conf not found
ERROR - Command "/work/build-run/bitbake/bin/bitbake -c build core-image-minimal" failed with error 1
BUILD_DONE label=first wall_seconds=25 rc=2
BUILD_DONE label=second wall_seconds=1 rc=2
=== ARTIFACTS ===
NO_IMAGE_DIR
```

`grep -c "from sstate"`、`Tasks Summary`、产物均为空；两次构建没有产生任何有效缓存指标。

## 2. 根因

`kas/base.yml` 的 `repos.bitbake` 只写了 `url` + `commit`，未显式声明 `layers`。kas 5.5 对没有 `layers` 键的 repo，默认把仓库根目录当作一个 layer 加入 `BBLAYERS`。但 bitbake 仓库不是 Yocto layer，只有 `conf/bitbake.conf`，没有 `conf/layer.conf`（容器内 `ls /work/build-run/bitbake/conf/` 仅有 `bitbake.conf`，`test -f .../layer.conf` → NO）。因此 bitbake 解析 bblayers 时找不到 layer.conf 而失败。

Stage B 的 `kas dump` 验收未触发该问题（dump 只展开配置、不解析 layer.conf），因此缺陷直到 Stage D 实际构建才暴露。这是 B-01/B-02 静态验收的固有盲区。

## 3. 修复过程

**首次尝试失败**：给 bitbake repo 写 `layers: []`，kas 5.5 的 schema 拒绝：

```text
ERROR - Config file validation Error:
{'url': 'https://git.openembedded.org/bitbake', 'commit': '51fd94a...', 'layers': []} is not valid under any of the given schemas
```

查容器内的 `kas/schema-kas.json` 确认：`layers` 的类型是 **object**，不是 list；描述明确「`.` is a valid value if the repo itself should be added as a layer」，且每个 layer 的值可设为 `disabled` 以「Exclude this layer from bblayers.conf」。

**最终修复**：把 bitbake 仓库自身的 layer（键 `.`）显式禁用，使其只作为工具仓库被 clone，不进入 `BBLAYERS`：

```yaml
  bitbake:
    url: https://git.openembedded.org/bitbake
    commit: 51fd94a67fa17650a9ff623492005972bbc7d26f
    layers:
      .: disabled
```

修复后 `kas dump` 返回 0，dump 输出中 bitbake 的 `layers` 为 `. disabled`（未再出现仓库根路径）。其余四个 repo 的 `layers` 声明保持不变（openembedded-core → `meta`、meta-yocto → `meta-poky`、meta-openembedded → `meta-oe`、meta-yp-distro → `meta-yp-distro`）。

## 4. 验证证据

修复后容器内验证：

```text
$ kas dump kas/yp.yml:kas/editions/ci.yml  → DUMP_RC=0
  dump 输出：bitbake.layers = { .: disabled }，不再含仓库根路径
$ cat build/conf/bblayers.conf
  BBLAYERS = " .../meta-openembedded/meta-oe .../meta-yocto/meta-poky .../meta-yp-distro .../openembedded-core/meta"
  不再包含 ${TOPDIR}/../bitbake
```

bitbake 不再被当 layer，原始 `layer.conf not found` 错误消失；构建推进到 recipe 解析（2002 .bb 解析完成、4630 任务排队），证明本问题已关闭。后续构建遇到的是另一独立问题（ISS-009 层依赖名，见另单）。

## 5. 关闭

- 关闭条件：bitbake 不再进入 BBLAYERS、`kas dump` 校验通过、构建推进过 layer 解析阶段——**均达成**。
- 关闭人 / 日期：zeek.zhao / 2026-11-25
- **下次如何避免**：`kas dump` 通过不等于 `kas build` 能跑；引入新 repo 时必须确认它是否真的是 layer——bitbake 这类工具仓库要用 `layers: { .: disabled }`（schema 要求 layers 是 object，`[]` 不合法），并在 S2 阶段做一次最小构建冒烟，不能把首次实跑留到 S5。
