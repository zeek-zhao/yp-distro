# YP-M0-ISS-007 · kas dump 容器验收的路径解析与写权限问题

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-007 |
| 状态 | Closed（已修正验收方式并验证） |
| 严重度 | 中（阻断验收命令，不影响 kas 配置本身） |
| 发现阶段 | Stage B 容器验收 |
| 关联 | DES-002、RV-002、交接 m0-resume-prompt §6.4 |

## 1. 现象

在 builder 容器内按交接 §6.4 执行验收，两次失败：

```
$ kas dump kas/yp.yml:editions/prod.yml
ERROR - Configuration file not found: /work/repo/editions/prod.yml   (exit 2)

$ kas dump kas/yp.yml:kas/editions/prod.yml
INFO - Cloning repository openembedded-core ...
ERROR - could not create work tree dir '/work/repo/openembedded-core': Permission denied
ERROR - fetch repos failed: error code 128
```

## 2. 根因

1. **路径解析**：kas 5.5 把 `:` 后的第二段配置按 cwd 解析，不按第一段所在目录；交接写的 `editions/prod.yml` 被解析成 `/work/repo/editions/prod.yml`。正确写法 `kas/yp.yml:kas/editions/prod.yml`。
2. **写权限**：kas dump 会 clone 全部 repos 到 cwd；宿主目录以只读方式挂给非 root 的 jenkins，clone 失败。且直接 clone 到仓库根会污染工作区。

## 3. 修复

- 验收命令路径改为 `kas/yp.yml:kas/editions/<name>.yml`（DES-002 §5 同步）。
- 验收方式改为：容器内把 `kas/` 与 `meta-yp-distro/` 复制到可写工作副本 `/work/kas-run`（jenkins 属主），cd 后跑 dump；用持久容器 + exec，repos 只 clone 一次，后续 dump/edition 复用。

## 4. 验证证据（真实输出）

见 Stage B 验收记录与 RV-002 补充；`DUMP_STABLE`、四个 `EDITION_OK` 均由修正后命令实跑产生。

## 5. 关闭

- 关闭条件：修正后命令在容器内产生 DUMP_STABLE + 4 EDITION_OK + commit pin 数 ≥ 4。
- 关闭人 / 日期：zeek.zhao / 2026-11-25
- **下次如何避免**： kas 多文件语法的后续文件路径按 cwd 解析，验收命令要在目标 kas 版本实跑校准，不能照抄文档；容器验收要给非 root 用户准备可写工作副本，不要把 clone 落到只读挂载点或仓库根。
