# YP-M0-ISS-015 · 指定的 kas 简写命令在当前目录布局下解析失败

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-015 |
| 状态 | Closed（2026-11-25，干净检出简写 dump 两次 rc=0 且 diff 空） |
| 发现时间 | 2026-11-25 |
| 作者 | zeek.zhao |
| 关联 | DES-002、DES-005、CHG-009、ISS-007 |
| 严重度 | 严重（统一写法若不落地会让 README/验收命令变成不可执行文本） |

## 1. 现象（只写观察到的事实）

- T6 要求全仓统一 kas 命令写法为 `kas/yp.yml:editions/prod.yml`。在仓库根 `/workspace/yp-distro` 使用 kas 5.5 实测该写法失败：

```text
$ kas dump kas/yp.yml:editions/prod.yml
2026-11-25 18:54:02 - INFO     - kas 5.5 started on Ubuntu noble
2026-11-25 18:54:02 - ERROR    - All concatenated config files must belong to the same repository or all must be outside of versioning control
SHORT_RC=2
```

- 同一 cwd 下 `kas dump kas/yp.yml:kas/editions/prod.yml` 成功（`LONG_RC=0`），与 ISS-007 的结论一致：kas 把 `:` 后的第二段按 cwd 解析，不按第一段所在目录解析；仓库根并没有 `editions/` 目录。
- 在干净检出中增加根级符号链接 `editions -> kas/editions` 后，同一条简写命令成功：

```text
$ ln -s kas/editions <tmp>/editions
$ cd <tmp> && kas dump kas/yp.yml:editions/prod.yml
SYMLINK_SHORT_RC=0
DUMP_LINES=49
```

## 2. 复现

```bash
cd /workspace/yp-distro
kas --version                                      # kas 5.5
kas dump kas/yp.yml:editions/prod.yml >/dev/null; echo SHORT_RC=$?   # 2（无符号链接时）
kas dump kas/yp.yml:kas/editions/prod.yml >/dev/null; echo LONG_RC=$?  # 0
TMP=$(mktemp -d); git archive HEAD | tar -x -C "$TMP"; ln -s kas/editions "$TMP/editions"
(cd "$TMP" && kas dump kas/yp.yml:editions/prod.yml >/dev/null); echo SYMLINK_SHORT_RC=$?
```

- 期望结果：统一后的简写命令可原样执行且 dump 成功。
- 实际结果：无符号链接时简写 rc=2；有符号链接时 rc=0。
- 首次出现于：提交 `b8be79e` / 本机 kas 5.5 实测（2026-11-25 18:54 UTC）。

## 3. 根因分析

- 直接原因：`editions/prod.yml` 相对 cwd 不存在；kas 判定两个配置不属于同一仓库而拒绝拼接。
- 根本原因：目录布局把 edition 放在 `kas/editions/`，而统一写法要求从仓库根以 `editions/` 访问；两者缺一个显式映射。
- 排除过的假设：不是 kas 版本差异（同一次实测中长写法 rc=0）；不是网络/仓库锁定问题（dump 已能 clone 并检出全部四个 pinned commit）。

- 关闭条件：干净检出中 `kas dump kas/yp.yml:editions/prod.yml` rc=0，两次 dump `diff -u` 为空；DES-002 写明路径解析规则。
