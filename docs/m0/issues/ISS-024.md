## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：本轮 §6 用 GitHub API 匿名查询 release `m0-s5-payload-full`，资产数为 9：`cache-full.part-00..07` + `cache-full.sha256`，**没有** `cache-full.manifest.json`。而 CHG-013「清单持久化」一行写「`manifests/full-slices-manifest.json` 作为 `cache-full.manifest.json` 上传 release `m0-s5-payload-full`」。
- 影响范围：文档契约口径；不影响消费端（消费端用仓库持久 manifest `manifests/cache-full.release.json` 与 `full-slices-manifest.json`）。

## 2. 复现

```bash
curl -s https://api.github.com/repos/zeek-zhao/yp-distro/releases/tags/m0-s5-payload-full \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(len(d["assets"]), [a["name"] for a in d["assets"]])'
# 9 ['cache-full.part-00', ..., 'cache-full.part-07', 'cache-full.sha256']
```

- 期望结果：若 CHG-013 契约成立，资产列表应含 `cache-full.manifest.json`。
- 实际结果：缺该资产。
- 首次出现于：CHG-013 写入该契约时；本轮 HEAD `88246d0` 实测。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：`scripts/cache/publish-manifest.sh` 的上传在历史上未实际对 release `m0-s5-payload-full` 执行（RV-013 T5 记录真实上传 UNVERIFIED，缺具名上传 secret）。
- 根本原因：文档先写了“已上传”契约，但未落地上传动作，形成文档与事实不符。
