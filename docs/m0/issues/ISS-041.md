# YP-M0-ISS-041 · ai-entry.sh 把带注记的完成态误判为未完成

| 项 | 值 |
|---|---|
| 文档编号 | YP-M0-ISS-041 |
| 状态 | Resolved（AI-011 / T1 已修，见 CHG-023、RV-022） |
| 关联 | YP-M0-CHG-023 / YP-M0.1-RV-022；AI-011 v1.0 §1/§2；分支 `feat-m0.1.3-ai-entry`（基线 `m0.1.2`=`8c28dc1`） |

## 1. 现象

`docs/m0/plan.md` 中 S6 状态为 `完成（Stage E 接线 + 契约收紧）`、S7 为 `完成 / 端到端已验`，均已完成。但 `bash scripts/ai-entry.sh` 仍把 S6 当作「下一步」，`bash scripts/ai-entry.sh --next` 继续要求「实现 Step S6」，误导执行方重做已闭环的工作。

## 2. 根因

`scripts/ai-entry.sh` 的 awk 判定用精确相等：

```awk
if (state != "完成") { printf ...; exit }
```

`完成（…）` / `完成 / …` 与字符串 `完成` 不相等，故被当成未完成。

## 3. 修复前输出（真实）

`bash scripts/ai-entry.sh`（节选）：

```text
进度（来自 docs/m0/plan.md）:
  ...
  S6   缓存打包与切分（80% 阈值） 完成（Stage E 接线 + 契约收紧）
  S7   缓存分片发布到容器仓库 完成 / 端到端已验
  ...

下一步   : S6 缓存打包与切分（80% 阈值）（完成（Stage E 接线 + 契约收紧））
取提示词 : scripts/ai-entry.sh --next
```

`bash scripts/ai-entry.sh --next`（首行）：

```text
继续 M0：实现 Step S6（缓存打包与切分（80% 阈值）），当前状态 完成（Stage E 接线 + 契约收紧）。
```

## 4. 修复

按 CHG-023：完成态判定改前缀语义 `done = (state ~ /^完成/ || state ~ /^已验/)`；`--next` 无后续 Step 时输出闭环提示并 exit 0；普通模式完成态输出 M0/M0.1 闭环 + M1 未立项；`PLAN_OVERRIDE` 支持可测试性。

## 5. 修复后输出（真实）

`bash scripts/ai-entry.sh`（尾部）：

```text
下一步   : M0/M0.1 已闭环；M1 未立项（需 PRD/范围评审）
取提示词 : 先写 M1 范围，再拉 feat-m1-*
```

`bash scripts/ai-entry.sh --next`（全文，exit 0）：

```text
M0 全部 Step 已完成；M0.1 已闭环；M1 未立项，先补 M1 范围/PRD 评审，不直接写 M1 代码。
```

临时 plan 三态样例见 RV-022 §1。

## 6. 验收口径

- 不把 `未完成` 误判为完成：`^完成` / `^已验` 前缀不匹配 `未完成`（首字为「未」），实测样例 D 仍选中 `未完成` 步。
- 不输出「实现 Step （）」空 Step：`--next` 对空 `next_row` 提前返回。
- 不自行发明 M1 需求：全部完成后只提示补 M1 范围/PRD，不写 M1 代码。
