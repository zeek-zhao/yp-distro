## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：
  - `docker push ghcr.io/zeek-zhao/yp-builder:wrynose-m0` → `denied: permission_denied: The token provided does not match expected scopes.`。
  - `gh api "/user/packages?package_type=container"` → HTTP 403 `Resource not accessible by personal access token`。
  - `GET https://ghcr.io/token?scope=repository:zeek-zhao/yp-builder:pull,push` → `{"errors":[{"code":"DENIED",...}]}`。
- 影响范围：镜像无法发布到 GHCR；S7（预热镜像发布）受阻；不影响本地镜像构建与验证。

## 2. 复现

```bash
export GH_TOKEN=<PAT>
echo "$GH_TOKEN" | docker login ghcr.io -u zeek-zhao --password-stdin   # Login Succeeded
docker tag yp-builder:wrynose-m0 ghcr.io/zeek-zhao/yp-builder:wrynose-m0
docker push ghcr.io/zeek-zhao/yp-builder:wrynose-m0    # denied: permission_denied
gh api "/user/packages?package_type=container"          # HTTP 403
```

- 期望结果：镜像推送到 GHCR，可被匿名拉取。
- 实际结果：login 成功但 push 被拒；packages 列表 API 403。
- 首次出现于：提交 `2dd387a` / 镜像 `ba1a5b8b7ecf`。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：PAT 的 fine-grained 权限未勾选 `write:packages`（GHCR 推送所需 scope）。
- 根本原因：令牌权限配置与发布目标不匹配；仓库 push（git）与包发布（GHCR）是两套独立 scope，前者可用不代表后者可用。
- 排除过的假设：
  - 非登录失败——`docker login` 返回 `Login Succeeded`；
  - 非镜像/标签问题——本地 tag 与构建均成功；
  - 非仓库名冲突——GHCR 仓库此前不存在（manifest unknown）。
- 安全约束：按 iso-mapping 第 7 节，不记录 token 明文，不尝试绕过权限。

## 5. 验证证据（Verifying 阶段填写）

```bash
# 临时闭环（当前环境实跑）
docker save ghcr.io/zeek-zhao/yp-builder:wrynose-m0 -o /tmp/yp-builder.tar
docker image rm ghcr.io/zeek-zhao/yp-builder:wrynose-m0
docker load -i /tmp/yp-builder.tar
docker run --rm ghcr.io/zeek-zhao/yp-builder:wrynose-m0 whoami   # 期望 jenkins
```

- 结论：部分通过。真实输出（2026-11-24）：
  - `docker save` → `/tmp/yp-builder-wrynose-m0.tar`（575M）；`docker image rm` → `removed OK`；
  - `docker load` → `Loaded image: ghcr.io/zeek-zhao/yp-builder:wrynose-m0`；
  - `docker run ... whoami` → `jenkins`；`id -u` → `1000`；`kas --version` → `kas 5.5`；OS → `Ubuntu 24.04.5 LTS`；
  - 挂载 `/work/downloads` 后 `touch` 探测 → `OK`（jenkins 可写）。
  - GHCR 真实发布：UNVERIFIED（token 缺 `write:packages`，push 被拒）。

## 6. 关闭

- 关闭条件：PAT 获 `write:packages` 后 push 成功。用户提供的独立 TOKEN（具备 write:packages）已将两镜像成功推送到 GHCR（见 ISS-005 第 5 节），本单就「原 PAT 权限不足」问题关闭；匿名拉取的可见性问题转 ISS-005 跟进。
- 关闭人 / 日期：zeek.zhao / 2026-11-24
- **下次如何避免**：发布前用 `gh api /user/packages?package_type=container` 与 GHCR token scope 探测确认权限；在 S7 设计中明确发布所需 scope 与 token 来源，区分 git push 与 package push 两套权限。
