## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：`README.md` 快速开始第 2 步仅一条 `bash scripts/bootstrap.sh --downloads ./downloads --sstate ./sstate`（line 51），无 UID 分支。CHG-014 后脚本默认目标为 1000，UID≠1000 的普通用户照抄会 `ERROR[2] UID_MISMATCH`、exit 2；root 照抄会把卷建在 1000 但 `docker run` 用默认 GHCR 1000 镜像才匹配（路径 A 尚可用），路径 B 用户会卡住。
- 影响范围：所有 UID≠1000 的新机用户照 README 快速开始；runbook §5.2 已有正确路径但 README 未指向/未展开。

## 2. 复现

```bash
grep -n "bash scripts/bootstrap.sh" README.md
# 51:bash scripts/bootstrap.sh --downloads ./downloads --sstate ./sstate   （唯一一条，无 --uid）
# uid=1234 隔离探针
runuser -u uid1234 -- bash scripts/bootstrap.sh --downloads /tmp/uid7/dl --sstate /tmp/uid7/sstate --min-free-bytes 0
# RC=2  ERROR[2] UID_MISMATCH
```

- 期望结果：README 第 2 步给出「二选一」的路径 A（`sudo --uid 1000`）与路径 B（`--uid $(id -u)`，先建 yp-builder:local），两个独立代码块。
- 实际结果：仅一条裸 bootstrap。
- 首次出现于：提交 `1d1ddb6`（AI-006 只补了「先 fetch 后 bootstrap」顺序，未拆 UID 分支）。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：README 为「最简示意」刻意只留一条命令，但 CHG-014 改默认 UID 后这条命令在 UID≠1000 上不再可执行。
- 根本原因：README 与 runbook §5.2 的 UID 决策未联动；README 既想「照抄可跑」又不展开分支，二者不可兼得。
- 排除过的假设及排除依据：脚本本身正确（显式 UID 探针 exit 0），不是脚本缺陷。
