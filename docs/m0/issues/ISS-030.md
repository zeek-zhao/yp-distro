## 1. 现象（只写观察到的事实）

- 观察到的输出／现象：
  - `manifests/cache-full.release.json` 写 `layout=two-stage`，但 release `part-00` HTTP Range 前 4 KB 实物顶层为 `downloads/ sstate/ yp-dl/`，无顶层 `downloads.tar`；RV-014 全量实跑 `STRUCT_OK mode=direct`。
  - `fetch-cache.sh` 把 `layout == two-stage` 当作「8 分片需 cat 重组」与「`--parts` 拒绝」的开关；`layout` 本应只描述归档内部布局，两个语义被混在一个字段。
  - 把 `layout` 改成 `direct`（反映真实布局）而不改重组判断，会让全量下载不再重组、直接把单个 1.5 GB 分片当整 tar 解包 → 全量取回被打断。
- 影响范围：换机取缓存的正常路径；release 资产本身无错；不影响已构建产物。

## 2. 复现

```bash
cd /workspace/yp-distro
curl -sL -r 0-4095 -o /tmp/part00.head \
  https://github.com/zeek-zhao/yp-distro/releases/download/m0-s5-payload-full/cache-full.part-00
strings /tmp/part00.head | grep -E 'yp-dl|downloads|sstate|downloads.tar' | head   # 无 downloads.tar 顶层
python3 -c "import json;d=json.load(open('manifests/cache-full.release.json'));print(d['layout'],d['expected_bytes'],len(d['assets']))"
# two-stage 11153387520 8
bash scripts/cache/fetch-cache.sh --mode release --dry-run --dest-parent /tmp/n --work /tmp/nw --release-tag m0-s5-payload-full 2>&1 | grep MODE_INFO
# MODE_INFO ... layout=two-stage dry_run=1
```

- 期望结果：`layout` 反映真实 direct 布局，且重组判断独立于布局字段。
- 实际结果：`layout=two-stage` 与实物 direct 矛盾；重组/`--parts` 判断依赖该字段。
- 首次出现于：提交 `b818251`（CHG-012 定义 manifest 时即混用，RV-014 实跑暴露矛盾）。

## 3. 根因分析（Analyzed 阶段填写）

- 直接原因：manifest 只有一个 `layout` 字段，既表达「tar 内部结构」又被脚本借用作「分片是否需重组」的开关。
- 根本原因：CHG-012 撰写时假设 release tar 由 `pack.sh` 产出（two-stage）；实物 release 为 direct，`layout` 无法同时承载两种语义。
- 排除过的假设及排除依据：不是发布资产错误——HTTP Range 与 RV-014 sha256/字节均一致；不是 `fetch` 解包 bug——`unpack_archive` 的 direct 探测正确。

## 5. 验证证据（Verifying 阶段填写）

```bash
python3 -c "import json;d=json.load(open('manifests/cache-full.release.json'));print(d['layout'],d['requires_reassembly'],d['expected_bytes'],len(d['assets']))"
# direct True 11153387520 8
bash scripts/cache/fetch-cache.sh --mode release --dry-run --dest-parent /tmp/n --work /tmp/nw --release-tag m0-s5-payload-full 2>&1 | grep -E 'MODE_INFO|EXPECTED_ARCHIVE'
# MODE_INFO mode=release tag=m0-s5-payload-full assets=8 layout=direct reassemble=1 dry_run=1
# EXPECTED_ARCHIVE name=cache-full.tar sha256=1c8126d4... bytes=11153387520
bash scripts/cache/fetch-cache.sh --mode release --parts 1 --dry-run --dest-parent /tmp/n --work /tmp/nw --release-tag m0-s5-payload-full 2>&1 | grep -i '--parts'
# ERROR: 分片归档不支持部分取片（requires_reassembly=true）
```

- 结论：通过（V4/V5 实跑；dry-run 显示 `layout=direct reassemble=1`，`--parts 1` 被明确拒绝；真实全量下载未重跑，按约束不下载 11 GiB，标 UNVERIFIED 复验方法见 RV-015）。

## 6. 关闭

- 关闭条件：字段拆分落地、dry-run 显示 `layout=direct reassemble=1`、`--parts` 仍拒绝、gate/vars 绿。
- 关闭人 / 日期：zeek.zhao / 2026-11-26
- **下次如何避免**：manifest 中「布局」与「消费方式」分字段表达；写入一致性校验，禁止用布局字段驱动重组逻辑。
