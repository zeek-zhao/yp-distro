## 1. 现象与证据

**首次构建**（wall 1679s，1931 tasks）：

```text
ERROR: llvm-project-source-22.1.8-22.1.8-r0 do_unpack: Bitbake Fetcher Error: UnpackError(
  'xz -dc /work/downloads/llvm-project-22.1.8.src.tar.xz | tar --extract --no-same-owner -f - failed with return value 2', ...)
NOTE: Tasks Summary: Attempted 1931 tasks of which 0 didn't need to be rerun and 1 failed.
Sstate summary: Wanted 2304 Local 0 Mirrors 0 Missed 2304 Current 0 (0% match, 0% complete)
BUILD_DONE label=first wall_seconds=1679 rc=2
```

**第二次构建**（wall 615s，无 ERROR 任务）：

```text
Sstate summary: Wanted 2304 Local 976 Mirrors 0 Missed 1328 Current 0 (42% match, 0% complete)
NOTE: Setscene tasks completed
NOTE: No reply from server in 30s (for command ping at 17:17:04.798213)
ERROR: Timeout while waiting for a reply from the bitbake server (60s at 17:17:46.908872)
BUILD_DONE label=second wall_seconds=615 rc=2
=== ARTIFACTS ===
NO_IMAGE_DIR
```

两次均未产出镜像。第二次 sstate 命中 976/2304（42%），证明卷复用生效。

## 2. 根因

1. **llvm do_unpack**：容器现场手动复现 `xz -dc … | tar --extract` 返回 `PIPE_EXIT=0 0`，`xz -t` 校验退出 0，文件 160M 完整、能解出 `llvm-project-22.1.8.src/`。判定为首次下载写入与解压并发导致的偶发解压失败，非源码包损坏、非配置缺陷。
2. **bitbake server timeout**：第二次执行到 `task 1338 file-native do_populate_sysroot` 后 server 30s/60s 无应答。属构建期间 server 通信偶发超时，非任务逻辑失败（second.log 无 ERROR 任务）。
3. **sstate 复用被削弱**：bitbake 首次初始化时警告 `Sstate directory is shared between several builds ... but hash equivalency database is inside this particular build directory`。清 build 会丢掉 hashserv DB，导致跨构建复用不完整——这是第二次只有 42% 命中的直接原因之一，通过 CHG-003 修复。

## 3. 修复

- 通过 CHG-003 在 `kas/base.yml` 增加 `BB_HASHSERVE_DB_DIR = "${SSTATE_DIR}"`（hashserv DB 落在共享卷，跨 build 保留）与 `BB_SERVER_TIMEOUT = "300"`（缓解偶发通信超时误判）。
- 复跑再败于 `gcc-source do_unpack`（`tar: Unexpected EOF in archive`），但两个 tarball 实测完好：`xz -t` 退出 0；gcc 包 `xz -dc | tar -tf` 列表到最后一个文件、RC=`0 0`。判定失败源为 32 线程满并发下巨型源码包并发解压的瞬时资源压力打断 `xz|tar` 管道，故追加 `BB_NUMBER_THREADS = "16"`（并发减半），并清理 work-shared 失败残留后重跑。
- `rm_work` 已在 ci edition 启用（`INHERIT += "rm_work"`，日志确认 `do_rm_work` 执行），磁盘余量 232G，非瓶颈。
- 保留已有 downloads/sstate 卷内容（已积累 996+ sstate 对象），重跑构建验证产物与复用；不视为"空卷首次"重验（首次冷构建数据已记录于上方）。

## 4. 验证证据（2026-11-25 重试成功）

```text

BUILD_DONE label=second wall_seconds=214  rc=0
Sstate summary (first) : Wanted 2054 Local 0    Missed 2054 (0% match)
Sstate summary (second): Wanted 2054 Local 2049 Missed 5    (99% match)
Tasks Summary (second) : Attempted 4083 of which 3829 didn't need to be rerun and all succeeded.
产物: core-image-minimal-qemux86-64.rootfs-20261124203504.ext4.zst (20M, file=Zstandard compressed data)
```

hashserv DB 落到 `${SSTATE_DIR}` 后跨构建复用完整：命中率从修复前的 42% 提升到 99%。`BB_SERVER_TIMEOUT=300` 后未再出现 server 通信超时。真正的失败根因（OOM）另见 ISS-011。

## 5. 关闭

- 关闭条件：构建成功产出 `core-image-minimal`，`file` 可识别；第二次有 `didn't need to be rerun` 原始行且命中率高于修复前的 42%——**均达成**（99% > 42%）。
- 关闭人 / 日期：zeek.zhao / 2026-11-25
- **下次如何避免**：大体积源码包的下载与解压偶发失败可重试并先用 `xz -t` 校验；共享 SSTATE_DIR 时必须把 hashserv DB 也放到共享路径，否则跨构建复用不完整；长构建适当提高 `BB_SERVER_TIMEOUT`。
