# YP-M0-ISS-021 · slice manifest 被 .gitignore 的 *.slice* 静默忽略

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-ISS-021 |
| 状态 | Closed（2026-11-25，改名后入库并验证 `git ls-files` 可见） |
| 发现时间 | 2026-11-25 |
| 作者 | zeek.zhao |
| 关联 | CHG-013、T3、T5、RV-013 |
| 严重度 | 中（清单未入库会导致换机后无法用 `merge.sh` 校验 GHCR 分片） |

## 1. 现象（只写观察到的事实）

- T3 生成 `manifests/cache-full.slices.json` 并执行 `git add manifests/` 后，提交 `4cd7a9b` 的 `git show --stat` 只列出 `cache-full.release.json` 与 `cache-sample.release.json`，未列出 slices 清单。
- `git ls-files manifests/` 只返回两个文件；文件在磁盘上存在但未进入索引。

## 2. 复现

```bash
git check-ignore -v manifests/cache-full.slices.json
# .gitignore:8:*.slice*	manifests/cache-full.slices.json
```

## 3. 根因分析

- 直接原因：`.gitignore` 第 8 行 `*.slice*` 同时匹配 `cache.slice.00` 这类运行时分片和文件名含 `.slice` 的 manifest（`cache-full.slices.json` 含子串 `.slice`）。
- 根本原因：`git add manifests/` 不会提示被忽略文件，提交前只看 `--stat` 容易漏掉；换机可交付性依赖该清单持久化，必须改文件名并验证索引。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施 | 不声称 manifest 已入库；在 T3 提交后立即开单 | zeek.zhao | 已执行 |
| 永久措施 | 改名为 `manifests/full-slices-manifest.json`（不含 `.slice` 子串），同步更新 runbook/RV-013/脚本 usage，并用 `git ls-files` 验证 | zeek.zhao | 已执行 |

## 5. 验证证据（Verifying 阶段填写）

```text
git check-ignore -v manifests/cache-full.slices.json
.gitignore:8:*.slice*	manifests/cache-full.slices.json

提交 ab8d2f3 后：

manifests/full-slices-manifest.json

grep -rn 'cache-full.slices.json' . --exclude-dir=.git
NO_OLD_REF
```

- 结论：通过——清单已入库，旧引用清零。

## 6. 关闭

- 关闭条件：已满足——`git ls-files` 包含三份清单，无旧文件名引用。
- 关闭人 / 日期：zeek.zhao / 2026-11-25。
- **下次如何避免**：新增交付文件后必须用 `git ls-files` 或 `git status --ignored` 核对是否真的入库，不能只看 `git add` 与提交 `--stat`。
