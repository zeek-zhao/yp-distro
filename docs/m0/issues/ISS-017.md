## 1. 现象（只写观察到的事实）

- Push `bdce224` 后用 PAT 触发 `workflow_dispatch`，发布 run `45606593806`：
  - `publish-cache` `success`、`publish-builder` `success`（CHG-010 凭据修复已生效）；
  - `prepare-cache-payload` `failure`、`publish-cache-slices` `skipped`。
- 该 job 日志中 `python3 -c` 脚本原文出现未被替换的 `{{ env.S5_PAYLOAD_ASSET }}`，并报错：

```text
Traceback (most recent call last):
  File "<string>", line 1, in <module>
    import json,sys; d=json.load(sys.stdin); print(next(a["url"] for a in d["assets"] if a["name"] == "{{ env.S5_PAYLOAD_ASSET }}"))
StopIteration
##[error]Process completed with exit code 1.
```

- 同一 job 的 env 中可见 `S5_PAYLOAD_ASSET: cache-payload-sample.tar.gz`（变量本身存在）。

## 2. 复现

```bash
export GH_TOKEN='<PAT>'
curl -sSL -H "Authorization: Bearer $GH_TOKEN" \
  'https://api.github.com/repos/zeek-zhao/yp-distro/actions/jobs/139178945705/logs' \
  | grep -n 'S5_PAYLOAD_ASSET\|StopIteration'
```

- 期望结果：表达式替换为 `cache-payload-sample.tar.gz`，找到资产并上传 `cache-payload` 制品。
- 实际结果：`StopIteration`，`prepare-cache-payload` 红，下游 job skipped。
- 首次出现于：run `45606593806` / 提交 `bdce224`。

## 3. 根因分析

- 直接原因：workflow 里写的是 `{{ env.S5_PAYLOAD_ASSET }}`，GitHub Actions 表达式语法是 `${{ ... }}`；少了 `$` 导致字符串原样传入 Python，资产名比较永不相等，`next()` 抛 `StopIteration`。
- 本地模拟时手工做了字符串替换，掩盖了这个拼写错误；真实 CI 暴露。
- 排除过的假设：不是 release 资产不存在（API 查询显示 `cache-payload-sample.tar.gz` 存在，size=18476612）；不是 token 权限（另外两个 job 已成功 push GHCR）；不是制品上传失败（流程在上传前的资产查询就退出）。

## 4. 措施

| 类型 | 内容 | 责任人 | 何时执行 |
|---|---|---|---|
| 临时措施 | 不填发布端到端 digest，保持 UNVERIFIED | zeek.zhao | 已执行 |
| 永久措施 | 把表达式改为 `${{ env.S5_PAYLOAD_ASSET }}`，并在 workflow 静态校验中断言无裸 `{{` 残留 | zeek.zhao | 本次修复 |

- 后续项：修复后重新 push + dispatch，取真实 run 与 digest。
