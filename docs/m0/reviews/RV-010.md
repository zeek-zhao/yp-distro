## 4. 结论与放行意见

**有条件通过。** 现有骨架没有违背红线（非 root、无缓存服务器、阈值基本集中、身份与署名合规），但**顺序倒置**导致三个核心判据悬空：缺 kas 入口（S2）、缺挂载验证（S4）、缺真实构建与真实缓存（S5）。在此状态下把 S6/S7 标「完成」，会让后续里程碑建立在不存在的缓存之上。

**放行条件**（按顺序，前一项不完成不进入下一项）：

1. 补 S2：`kas/yp.yml`、`base.yml`（repos 全部 commit 锁定）、四个 edition、qemux86-64 machine；随后重跑判据 6 两次 `kas dump` 一致性
2. 补 S4：`bootstrap.sh`、`preflight.sh`；把判据 3、4 的「通过」先改回 `UNVERIFIED`，用「删容器重建后下载仍在」的真实输出重验
3. 做 S5：真实构建产出镜像与缓存；记录两次耗时与命中率
4. 改 S6/S7 结论：S6 降为「部分完成」直到切分接入发布流程；S7 的 B-08 从「已验证」降为「基线镜像已验证，真实缓存未验证」
5. 修 F-04、F-05、F-06、F-08、F-10；F-05 的阈值改为由 `threshold.conf` 注入生成 `cache-meta.json`
