### 机器性能评估与 Yocto 参数取值（回应「按机器性能给参数」）

宿主 `free` 显示 123Gi、`nproc` 显示 32，但**真实可用配额受 cgroup 约束**（已实测无法提升）：

```text
[CPU]     nproc=32  但 cpu.max=400000 100000 → 有效配额 4 核
[内存]    free=123Gi 但 /sys/fs/cgroup/memory.max=8589934592 → 限额 8GB
[磁盘]    overlay 256G, 可用 233G（非瓶颈）
[提配尝试] 写 memory.max / cpu.max → permission denied
          swapon /swapfile → Operation not permitted
          写 vm.swappiness → permission denied
```

据此把并发参数从 32/16 线程下调为与真实配额匹配的值（ISS-011 / CHG-005）：

```text
BB_NUMBER_THREADS = "4"      # 4 线程 ≈ 4 核有效配额，1:1
PARALLEL_MAKE     = "-j 2"   # 最坏 4×2=8 编译进程，8GB 内存内受控
BB_HASHSERVE_DB_DIR = "${SSTATE_DIR}"   # hashserv DB 落共享卷（CHG-003）
BB_SERVER_TIMEOUT = "300"               # 放宽 server 通信窗口（CHG-003）
ci.yml: INHERIT += "rm_work"; DISTRO_FEATURES:remove = "opengl x11 wayland vulkan"（CHG-004，裁图形栈降内存峰值）
```

修复前 5 次构建因 OOM 反复失败（容器 cgroup `oom_kill` 累计 9 次，`cc1plus` 收到 Killed 信号）；按上表调参后本轮两次构建均 `rc=0`，`oom_kill` 不再随构建增长。
