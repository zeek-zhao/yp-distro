## 1. 背景

m0-prompt 第六节同时要求「本分支为孤立分支，与 main 无共享历史」与「S0 后向 main 开 draft PR，PR 触发 CI」。二者在 GitHub 上互斥：创建 PR 要求 base 与 head 有共同祖先，而孤立分支没有（ISS-002 实测报错）。必须在两个方案间裁决，否则 M0 后续 Step 的评审与 CI 触发方式无从确定。

## 2. 可选方案

| 方案 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A | 维持孤立分支，不向 main 开 PR；评审用 commit diff + 评审记录（RV-），CI 用 `workflow_dispatch` 指定分支触发 | 保留 S0 已确定的孤立分支结构；不改写历史；与「不考虑 main」一致 | 无 PR 在线评审界面；CI 需手动 dispatch | 采用 |
| B | 放弃孤立分支，从 main 切出并 cherry-pick 现有提交，走 CHG 改分支策略，恢复 PR 流程 | 可用 PR 与自动 CI | 改写 S0 已定分支拓扑；违反「不考虑 main」；需重放提交、打乱孤立项 | 否 |

## 3. 决策与理由

- **选定方案**：A（用户/人类批准，2026-11-24）。
- **关键理由**：用户明确「使用方案 A，与 main 无共享历史，也不考虑 main 分支」；孤立分支是本里程碑刻意选择的结构，不应为迁就 PR 而重放历史或引入 main。
- **被否方案的原因**：方案 B 需要以 main 为基线重放提交，与「不考虑 main」直接冲突，且会推翻 S0 已完成的孤立分支事实。

## 4. 影响面

| 维度 | 影响 |
|---|---|
| 工作流 | 不开 PR；评审依据为 commit diff + `RV-` 记录；CI 由 `workflow_dispatch` 触发 |
| 文档 | 改写 m0-prompt 第六节、AGENTS.md 相关表述；ISS-002 关闭；deviations 第 1 条标记为已批准 |
| 提交 | 提交规范不变（一 Step 一提交，带 `Refs:`/`Doc:`） |
| 门禁 | `.github/workflows/m0.yml` 需支持 `workflow_dispatch`（S8 落地） |

## 5. 何时复看

- 触发条件：若将来决定让 M0 并入 main，则须新开 ADR 并走 CHG，重新评估 PR 策略；在此之前不主动改回方案 B。
