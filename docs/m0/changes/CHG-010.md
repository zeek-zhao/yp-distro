## 1. 变更内容

- 变更前：`publish-builder` / `publish-cache` / `publish-cache-slices` 的 `docker/login-action` 使用 `${{ github.actor }}` + `${{ secrets.GITHUB_TOKEN }}`。
- 变更后：

| 契约项 | 新值 |
|---|---|
| 登录用户名 | `${{ env.OWNER }}`（固定 `zeek-zhao`，与 PAT 归属一致） |
| 登录密码 | `${{ secrets.GHCR_PAT }}`（用户提供的具名 secret，具备 `write:packages`） |
| token 入库 | 禁止；仅通过 GitHub Actions encrypted secret 保存，仓库与 git 历史中无明文 |
| `permissions` 段 | 保留 `contents: read` / `packages: write`（与 secret 并存，不改变工作流最小权限声明） |

## 2. 为什么要改

- 事实依据：run `45601074345` 中 `publish-builder` 与 `publish-cache` 在 push 阶段被 GHCR 拒绝 `denied: permission_denied: write_package`（ISS-016 §1）；仓库 Actions 默认 workflow 权限为 `read`，孤立分支上注入的 `GITHUB_TOKEN` 无法写包。
- 此前成功的镜像推送（ISS-004/005）使用的是用户独立 TOKEN，不是 `GITHUB_TOKEN`。本变更把这一事实固化为显式契约。
- `workflow_dispatch` 与受限 `push` 两种触发方式都保持可用。
- **事实补充（2026-11-25）**：CHG-007 记录的「孤立分支 dispatch 不可用」仅对匿名/`GITHUB_TOKEN` 成立；使用本次提供的 PAT（`repo`/`workflow` 范围）执行 `gh workflow run m0.yml --ref feat-m0-kas-bootstrap` 返回 rc=0，并成功触发 run `45606593806`、`45606884016`、`45607197090`。故 L-01 应表述为「低权限凭据下 dispatch 不可用」，不再作为绝对限制。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | 新增 secret 名 `GHCR_PAT`；不改变阈值、变量索引、KAS 配置 |
| 目录与脚本 | 仅 `.github/workflows/m0.yml` 三处 `docker/login-action` |
| 门禁 | `gate.sh` / `check-vars.sh` 不变；G2 仍只查阈值字面量 |
| 已产出镜像 | 既有 `yp-builder:wrynose-m0`、`yp-cache:wrynose-m0` tag 可被覆盖更新（同一 tag 重新发布） |

## 4. 回滚方式

- 回滚命令：`git revert <本提交 SHA>`；同时在仓库 Settings → Secrets 删除 `GHCR_PAT`。
- 回滚后如何验证：`git grep 'GHCR_PAT'` 无命中；三个 job 恢复 `password: ${{ secrets.GITHUB_TOKEN }}`。

## 5. 验证方式

```bash
python3 - <<'PY'
import yaml
w = yaml.safe_load(open('.github/workflows/m0.yml'))
for name in ('publish-builder','publish-cache','publish-cache-slices'):
    s = w['jobs'][name]['steps']
    login = next(x for x in s if 'docker/login-action' in str(x.get('uses','')))
    assert login['with']['password'] == '${{ secrets.GHCR_PAT }}', (name, login)
    assert login['with']['username'] == '${{ env.OWNER }}', (name, login)
print('LOGIN_CONTRACT_OK')
PY
git grep -nE 'ghp_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9]{20,}' && echo 'TOKEN_LEAK' || echo 'NO_TOKEN_IN_REPO'
```

真实凭据是否可用以 push run 结果为准：`publish-builder` / `publish-cache` 两个 job 必须 success。
