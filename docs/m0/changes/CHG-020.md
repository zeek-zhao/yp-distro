## 1. 变更内容

### 1.1 `scripts/cache/fetch-cache.sh` ghcr 段（K-8，原 P3 可选项，本轮按 §6.4 修复）

- 变更前：
  - ghcr 段在 pull 循环后才 `check_target`——非空目标要白下 11 GiB 才发现占用。
  - 只按 tag 拉取（`docker pull "$im"`），不按 manifest 的 `digest`。
  - 不校验本地镜像 `RepoDigests` 与 manifest digest 是否一致。
  - `unpack_archive` 只识别 `downloads.tar+sstate.tar`（two-stage）与 `downloads/+sstate/`（direct）两种布局。
- 变更后：
  - **check_target 前置**：docker 可用性检查后立即 `check_target`，非空目标在任意 pull 之前 exit 1（实测 0 秒拒绝、无 `PULL_OK`）；解包前保留第二次检查。
  - **按 digest 拉取**：有 `digest` 时 `pull_ref="${im}@${dg}"`，`docker pull "$pull_ref"`；`docker image inspect ... --format '{{range .RepoDigests}}...'` 校验含 manifest digest，打印 `DIGEST_OK ... repo_digest_match=yes`；不符 die。
  - **DIGEST_FALLBACK**：manifest 无 digest 时回退按 tag 拉取并打印 `DIGEST_FALLBACK ... reason=manifest_digest_absent`。
  - **第三种布局支持**：`unpack_archive` 新增 `yp-dl.tar+yp-st.tar` 分支（mode=`two-stage-yp`），内层解包后把 `yp-dl/`→`downloads/`、`yp-st/`→`sstate/` 归一。
  - dry-run 的 `SLICE_IMAGE` 增加 `pull_ref=digest|tag` 与 `DIGEST_FALLBACK=1` 标注。
- 不改：分片 `bytes`/`sha256`/`digest` 的读取与校验逻辑；release 段；unpack-only 段；退出码语义（0 成功 / 1 校验失败 / 2 参数错误）。

### 1.2 `manifests/full-slices-manifest.json`（ISS-036 + 布局确认）

- **ISS-036 笔误修复**：slice 1 的 `sha256` 字段原为 63 字符截断值 `fbe9e356…d54`（末尾缺 `c`），补全为真实 64 字符 `fbe9e3567a87cc427a5e016b5e5b54c797ff8b2e4b4e6ebcbbe92bb47666d54c`。从 GHCR 镜像实际提取 `cache.slice.01` 计算 sha256 与该值一致。仅补一个字符，非篡改校验值。
- **布局确认**（§6.4 E3 第 3 点）：`layout` 由 `UNVERIFIED` → `two-stage-yp`；`layout_note` 更新为实测结论（顶层 `yp-dl.tar`+`yp-st.tar`，内层 `yp-dl/` 1288 文件、`yp-st/` 6945 文件，各带 `.yp-volume`）。
- 不改：`total_bytes`（11153397760）、`source_sha256`（a8870b50…）、`total_slices`、`slice_max_bytes`、`requires_reassembly`、两片 `bytes`/`image`/`digest`/`index`、slice 0 的 `sha256`。diff 仅 3 行（layout / layout_note / slice1 sha256 补 c）。

## 2. 为什么要改

- K-8：`--mode ghcr` 从未真实端到端执行，pull 时机、digest 校验、目标检查顺序均未按真实故障路径验证。
- ISS-036：ghcr 全链路真实执行暴露 manifest 分片 01 sha256 字段截断一位（历史自 `13ec6f5a`），导致分片校验永久 exit 1，字节数却一致——静态检查无法发现。
- 布局：GHCR 源 tar 布局长期 `UNVERIFIED`；E3 真实拉取确认是与 release direct、pack.sh two-stage 都不同的第三种布局，脚本此前不识别，ghcr 链路无法完成解包。

- 回滚后验证：`bash scripts/cache/fetch-cache.sh --mode ghcr --dry-run ...` 应显示 `pull_ref=tag`（无 digest 处理）。
