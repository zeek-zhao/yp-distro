# YP-M0-CHG-016 · 全量清单分发契约降级为「仓库持久 manifest + 上传 UNVERIFIED」

## 1. 变更内容

- 变更前：
  - CHG-013「清单持久化」：`manifests/full-slices-manifest.json` 作为 `cache-full.manifest.json` **已上传** release `m0-s5-payload-full`（ISS-024：API 实测无该资产）。
  - `fetch-cache.sh`：无 `--keep` 时 `trap 'rm -rf "$WORK"'` 无条件删除整个 `--work` 目录（ISS-025）。
  - `fetch-cache.sh`：`--parts` 对 two-stage 归档未实现重组，静默把单片当整 tar（ISS-026）。
- 变更后：
  - CHG-013 契约改为：`cache-full.manifest.json` 的**权威副本在仓库 `manifests/`**（`cache-full.release.json` / `full-slices-manifest.json`），release 上传标 `UNVERIFIED`（本轮无具名上传 secret，不伪造成功）。
  - `fetch-cache.sh`：仅当 `--work` 目录由脚本自建时才整体清理；用户已存在的目录只清理脚本自身工件（ISS-025）。
  - `fetch-cache.sh`：`--parts` 对 two-stage 的部分取片显式报错拒绝（ISS-026）。

## 2. 为什么要改

- 本轮 GitHub API 实测 release `m0-s5-payload-full` 只有 9 个资产（8 分片 + `cache-full.sha256`），无 `cache-full.manifest.json`（ISS-024/REPRO）；CHG-013「已上传」与事实不符。
- 代码走查确认 trap 无差别 `rm -rf "$WORK"`（ISS-025/REPRO）、`--parts` two-stage 未重组（ISS-026/REPRO）。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | 清单分发口径由「已上传」改为「仓库持久 + 上传 UNVERIFIED」；无新阈值 |
| 目录与脚本 | `docs/m0/changes/CHG-013.md`、`scripts/cache/fetch-cache.sh` |
| 门禁 | gate G1 语法需通过；G2 阈值不变；check-vars 不变 |
| 已产出的镜像 / 缓存 | 不改 release 资产、不改已发分片；消费端仍用仓库 manifest |

## 4. 回滚方式

- 回滚命令：`git revert <本提交>`，恢复 CHG-013 原契约与 fetch-cache.sh 原逻辑。
- 回滚后如何验证：`grep 清单持久化 CHG-013` 回到「已上传」；fetch-cache.sh 走查 trap 恢复无条件删除。

## 5. 验证方式

```bash
bash -n scripts/cache/fetch-cache.sh                       # G1 语法 OK
# K-4：在 /tmp 预建带哨兵的 work 目录，跑不带 --keep 的 fetch，确认哨兵仍在
# K-5：--mode release --parts 1 ... 应 die 并打印 ISS-026
bash scripts/gate.sh && bash scripts/check-vars.sh         # GATE_PASS / VARS_OK
```
