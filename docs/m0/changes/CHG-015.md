## 1. 变更内容

- 变更前：`docker/cache-provenance.json`、`docker/cache-meta.json` 中 `payload_sha256=1c8126d4…` 配 `payload_bytes=11153397760`；`CHG-013` 字段表写 `payload_bytes=11153397760`；`acceptance.md` 判据 7 写“tar 11,153,397,760 B / sha256 1c8126d4…”。
- 变更后：上述引用统一为 `1c8126d4… ↔ 11153387520`（release 8 分片之和）。`docker/cache-meta.json` 由 `gen-meta.sh` 从改后的 provenance 重新生成。GHCR 切片源 tar（`a8870b50…` / 11153397760）的历史记录保持原样，不被改写。

## 2. 为什么要改

- 本轮 §6 dry-run 实测 `EXPECTED_ARCHIVE ... sha256=1c8126d4… bytes=11153387520`，`manifests/cache-full.release.json` 的 `expected_bytes=11153387520`，GitHub API 8 分片之和亦为 11,153,387,520 B。provenance 的 11,153,397,760 B 属于另一个 tar（`a8870b50…`，见 runbook §2 / RV-013 事实核对第 3 条），是交叉配对的事实错误（ISS-023）。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | provenance 的 `payload_bytes` 数值；不引入新变量；阈值仍只在 threshold.conf |
| 目录与脚本 | `docker/cache-provenance.json`、`docker/cache-meta.json`（重生成）、`docs/m0/changes/CHG-013.md`、`docs/m0/acceptance.md`（判据 7 + 升版） |
| 门禁 | gate G2 要求 cache-meta.json 与 gen-meta 逐字一致——重生成后满足 |
| 已产出的镜像 / 缓存 | 不改 release 资产、不改 GHCR 分片；仅元数据与文档事实口径 |

## 4. 回滚方式

- 回滚命令：`git revert <本提交>`，恢复 provenance 旧值与旧 cache-meta.json；CHG-013/acceptance 文字还原。
- 回滚后如何验证：`grep payload_bytes` 回到 11153397760，gate G2 逐字一致（因 cache-meta 同步还原）。
