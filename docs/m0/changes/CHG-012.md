## 1. 变更内容

- 变更前：release `m0-s5-payload-sample` 仅含 18 MB 抽样载荷（downloads 3 文件 + sstate 12 文件），用于证明制品交接链路。
- 变更后：

| 契约项 | 新值 |
|---|---|
| 全量载荷 | `/tmp/yp-dl`（6,177,052,713 B / 1288 文件）+ `/tmp/yp-st`（4,959,814,019 B / 6945 文件），合计 11,136,866,732 B |
| 归档方式 | 单 tar（顶层 `downloads/`、`sstate/`）按 1500 MiB 分片为 release 资产，资产名 `cache-full.part-NN`，置于 tag `m0-s5-payload-full` |
| 资产大小上限 | 每片 < 2 GB（GitHub release 单资产限制） |
| GHCR 分发 tag | 全量缓存镜像 `yp-cache:wrynose-m0-full`；全量分片 `yp-cache:wrynose-m0-full-part-NN`（与样本 tag 并存，不覆盖已验证 tag） |
| 验证方式 | 分片重组 sha256 == 原 tar sha256；用同一 `pack.sh`/`gen-meta.sh`/`split.sh` 链路产出分片；push 后由 `docker buildx imagetools inspect` 与 GHCR registry API 双重核验 digest |

## 2. 为什么要改

- CHG-011 只用了抽样载荷，用户要求用全量 S5 构建缓存上传并重新验证。
- GitHub release 单资产上限 2 GB，11 GiB 全量载荷必须分片；GitHub Actions 托管 runner 可用磁盘不足以同时容纳 11 GiB 载荷、tar 与切片，因此全量链路在本地（沙箱，228 GB 可用）执行同一脚本与 docker 命令，CI 仍保留样本载荷的端到端证据。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 外部状态 | 新增 release tag `m0-s5-payload-full` 及分片资产；新增 GHCR 全量 tag；既有样本资产与 tag 不变 |
| 仓库文件 | 不改 workflow、不改阈值、不改脚本；仅新增/更新记录文档 |
| 门禁 | `gate.sh` / `check-vars.sh` 不变 |
| 判据 7 | 发布端到端结论保持「通过」，另补全量载荷的独立验证证据 |

## 4. 回滚方式

- 删除 release tag `m0-s5-payload-full` 与 GHCR `*-full*` tag；仓库 `git revert <本提交 SHA>` 仅删除记录。
- 回滚后验证：GitHub API 查询该 tag 返回 404；GHCR registry API 查询 full tag 返回 404/无版本。

## 5. 验证方式

```bash
# 归档完整性
sha256sum cache-full.tar
cat cache-full.part-* > cache-full.reassembled.tar
sha256sum cache-full.reassembled.tar   # 两值必须一致
tar -tf cache-full.reassembled.tar | grep -cE '^(downloads|sstate)/'   # 8233

# 发布链路（与 workflow 同一脚本）
bash scripts/cache/pack.sh --src ... --src ... --out /tmp/full.tar
bash scripts/cache/gen-meta.sh
bash scripts/cache/split.sh --in /tmp/full.tar --out /tmp/full-slices
bash scripts/cache/merge.sh --in /tmp/full-slices --out /tmp/full-merged.tar
sha256sum /tmp/full.tar /tmp/full-merged.tar

# GHCR 独立核验
curl -sS -o /dev/null -D - \
  -H "Authorization: Bearer <anon-token>" \
  -H 'Accept: application/vnd.oci.image.index.v1+json' \
  https://ghcr.io/v2/zeek-zhao/yp-cache/manifests/wrynose-m0-full-part-00 | grep -i docker-content-digest
```
