## 1. 变更背景

RV-010 F-05/F-07/F-11 三项待收口：`cache-meta.json` 写死字节数、`split.sh` 的 `--max-bytes` 覆盖参数使阈值可绕过、`SHA256SUMS.slice` 残留未清理。同时分片未接入发布链路（F-07），需按 ADR-005 方案 1 定义分片 tag 契约。

## 2. 删除的约束/接口

| 删除项 | 原位置 | 说明 |
|---|---|---|
| `split.sh --max-bytes` CLI 参数 | `scripts/cache/split.sh` | 允许绕过 threshold.conf，违反约束 8；改为 `YP_SPLIT_MAX_BYTES` 环境变量并打印 WARN |
| `SHA256SUMS.slice` 产物 | `scripts/cache/split.sh` | 每片 sha256 已记录在 manifest.json，重复产物属 F-11 残留，merge 不应再依赖它 |
| `cache-meta.json` 硬编码 `slice_max_bytes`/`upload_timeout_sec` | `docker/cache-meta.json` | 改由 `gen-meta.sh` 从 threshold.conf 生成 |

## 3. 新增/替换的约束/接口

| 新增项 | 新值/规则 | 所在文件 | 理由 |
|---|---|---|---|
| `gen-meta.sh` | 从 threshold.conf 读常量生成 cache-meta.json | `scripts/cache/gen-meta.sh` | F-05：数值唯一源，改阈值后重新生成随之变化 |
| `YP_SPLIT_MAX_BYTES` | 环境变量覆盖（仅测试用，打印 WARN） | `scripts/cache/split.sh` | 保留测试灵活性但显式标注非常规路径 |
| 分片 tag | `yp-cache:wrynose-m0-part-NN` | ADR-005、workflow | 每片一个镜像 tag（方案 1） |
| manifest `source_sha256` | 源 tar 的 sha256 | `split.sh` 生成、`merge.sh` 比对 | 合并后可直接与源比对，闭环完整性 |

## 4. 影响

- 阈值仍只在 `threshold.conf` 定义（约束 8），`gen-meta.sh` 与 `split.sh` 均 source 该文件。
- `merge.sh` 验收口径不变（缺片 exit 1、sha256 一致），新增对 `manifest.json` 的 `source_sha256` 比对（若字段存在）。
- 发布 workflow 新增分片 job，但孤立分支不可 dispatch（L-01），端到端触发本次标 UNVERIFIED。
- 空壳缓存镜像结论降级（F-02）：仅布局基线，真实载荷待 S5 产物。

## 5. 回滚

- `git revert` 本提交；恢复 `cache-meta.json` 硬编码、`split.sh --max-bytes`、`SHA256SUMS.slice` 产物。
- 回滚后验证：`grep -- --max-bytes scripts/cache/split.sh` 有命中、`gen-meta.sh` 不存在、workflow 无分片 job。
