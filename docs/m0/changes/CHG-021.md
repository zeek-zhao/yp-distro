## 1. 变更内容

### 1.1 `scripts/build/threads.sh`（新增，只读分级诊断）

- 读 `docker info` 的 `NCPU` / `MemTotal`（**不用宿主 shell 的 `nproc`/`/proc/meminfo`**——宿主 shell 被 cgroup 限 4c/8G，daemon 实为 32c/123GiB）。
- 分级表：standard(cpus≥32 且 mem≥120GiB)→32/-j16；mid(≥16/≥32)→16/-j8；small(≥8/≥16)→8/-j4；legacy(其他)→4/-j2。
- 支持显式覆盖 `YP_BUILD_THREADS`（正整数）/ `YP_PARALLEL_MAKE`（`-j <正整数>`），非法值 exit 1。
- 输出 `RESOURCE_TIER/CORES/MEM_GB` + 可 `eval` 的 `export` 赋值；daemon 不可用 exit 1，不静默回退。
- 用途：分级诊断 + verify-env 的 `SUGGEST_*` 唯一实现（不重复阈值表）；**不作为 bitbake 变量传递通道**（见 1.2 / ISS-037）。

### 1.2 `kas/base.yml`（构建并发动态化）

- 变更前：`BB_NUMBER_THREADS = "4"`、`PARALLEL_MAKE = "-j 2"` 写死（ISS-011 的 8GB 回退值，在 32c/128G 机器上未用满）。
- 变更后：
  ```bitbake
  BB_NUMBER_THREADS = "${@oe.utils.cpu_count()}"
  PARALLEL_MAKE = "-j ${@oe.utils.cpu_count() // 2}"
  ```
- 按 bitbake 进程可见 CPU 动态分级：32c→32/-j16、16c→16/-j8、8c→8/-j4、4c→4/-j2（与 threads.sh 分级表一致）；8GB 历史回退由 4c→4/-j2 自动保留。
- **偏离 AI-009 §2.2 字面写法**：提示词示例为 `${@os.environ.get('YP_BUILD_THREADS','4')}`，实测在 kas 5.5 + 本 bitbake 下 `os.environ` 被隔离、注入无效（ISS-037），故改用 bitbake 原生 `oe.utils.cpu_count()` 达成同一目标（按资源分级 + 默认回退），属代码与文档对齐（硬边界 6），不弱化 `AGENTS.md` §2.1。
- 不改 `DL_DIR`/`SSTATE_DIR`/`BB_HASHSERVE`/`BB_SERVER_TIMEOUT` 等其他契约。

### 1.3 接线与变量契约

- `docs/runbook-new-machine.md` 步骤 7、`docs/ai/m0-new-machine-test-prompt.md` §7：`docker run` 前 `eval "$(bash scripts/build/threads.sh)"`；保留容器 `docker inspect` 三项 0/0/0 与不加 `--cpus`/`--memory`；新增 `bitbake-getvar` 确认并发。
- `scripts/verify-env.sh`：新增 `SUGGEST_BUILD_THREADS` / `SUGGEST_PARALLEL_MAKE`，调用 threads.sh（不重复阈值）。
- `scripts/check-vars.sh` / `docs/m0/variable-index.md`：#10/#11 断言从写死 `4`/`-j2` 改为 `oe.utils.cpu_count()` 表达式（仍能检出把动态分级改回写死）。
- `scripts/gate.sh` G6：防写死 32/-j16、要求 cpu_count 表达式在位。
- `.github/workflows/m0-gate.yml`：executable bit 步骤加 `scripts/build/threads.sh`。

## 2. 为什么要改

- B1 决策：标准 32c/128G 不得沿用 8GB 的 4/-j2 固定值，须按 Docker 可见资源分级。
- RV-019 已在全配额跑通构建，但 bitbake 并发仍是 4/-j2（未用满）；本轮让并发真正按资源生效。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 构建并发 | 高配机自动升到 32/-j16；4c/8G 自动回退 4/-j2；低配不 OOM |
| 构建产物 | 不变（同一 prod edition、同一 ext4） |
| 缓存/发布契约 | 不改 DL_DIR/SSTATE_DIR/hashserv/分片/manifest |
| 门禁 | gate/vars 仍绿；G6 防回归 |

## 4. 回滚方式

`git revert` 本提交恢复写死 4/-j2（高配机回到未用满状态）。恢复 `${@os.environ.get}` 会重现 getvar=4（ISS-037），不建议。

## 5. 验证方式

见 `docs/m0.1/reviews/RV-020.md`：threads.sh 输出、fresh bitbake-getvar=32/-j16、docker inspect 0/0/0、两次 prod 构建、CPU/内存采样、4c/8G 边界。
