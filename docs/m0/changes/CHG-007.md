## 1. 变更内容

- 变更前：`.github/workflows/m0.yml` 仅 `on: workflow_dispatch`；`ISS-005`/`DES-007` 的表述是「孤立分支不可 dispatch，Actions 自动发布不可用」，`plan.md`/`acceptance.md` 据此把发布链路整体写为受 L-01 阻断。
- 变更后：`m0.yml` 保留 `workflow_dispatch`（供并入 main 后使用），新增**受限 `push`**：

```yaml
on:
  workflow_dispatch:
  push:
    branches:
      - feat-m0-kas-bootstrap
    paths:
      - 'docker/**'
      - 'scripts/cache/**'
      - 'kas/**'
```

- 口径同步：`workflow_dispatch` API 在孤立分支不可用是事实；**push 事件可用**也是事实（`m0-gate.yml` 已由 push 触发并产生 run `45594520683`）。两者不可混为「CI 全部阻断」。

## 2. 为什么要改

- 硬证据：GitHub Actions run `45594520683`，`event=push`、`head_branch=feat-m0-kas-bootstrap`、`head_sha=b072417`、workflow `.github/workflows/m0-gate.yml`，公开 API 可见且结论 `failure`（失败在 check-vars.sh，见 ISS-013）。这证明方案 A 的孤立分支**能由 push 触发 workflow**。
- ISS-005 中 `POST .../m0.yml/dispatches → 404` 只证明 dispatch 入口不可用；当时把它推广为「Actions 自动发布整体不可用」口径过宽。
- 发布链路仍需 S5 载荷（T3 修复「仓库内不存在的 `./cache-payload` 冒充」）；因此受限 push 只解决**触发**问题，不解决载荷问题，二者分别记录。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | 触发契约由「仅 dispatch」变为「dispatch + 受限 push」；阈值常量不变 |
| 目录与脚本 | 仅 `.github/workflows/m0.yml` 的 `on:` 段；`m0-gate.yml` 不动 |
| 门禁 | `gate.sh`/`check-vars.sh` 不变；判据 8 仍按本地 + CI push run 双证据 |
| 已产出的镜像 / 缓存 | 无；本变更不推送任何镜像，不改动 GHCR 既有 tag |

## 4. 回滚方式

- 回滚命令：`git revert <本提交 SHA>`，或手工删去 `m0.yml` 的 `push:` 段。
- 回滚后如何验证：`grep -A6 '^on:' .github/workflows/m0.yml` 只剩 `workflow_dispatch:`；下一次 push 不再产生 M0 publish run（dispatch 仍不可用）。

## 5. 验证方式

```bash

python3 -c "import yaml; d=yaml.safe_load(open('.github/workflows/m0.yml')); print(list(d[True] if True in d else d['on']))"
# 期望：['workflow_dispatch', 'push']，且 push.branches/paths 与本文一致

# CI 侧：推送触发路径变更（kas/**、docker/**、scripts/cache/** 任一）后查看 run

#      若缺 S5 载荷则按 T3 明示失败，不记为「workflow 未触发」。
```
