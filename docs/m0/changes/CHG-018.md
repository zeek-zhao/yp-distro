## 1. 变更内容

- 变更前：
  - UID≠1000 的路径 B 文档命令漏显式 `--uid/--gid`，构建 `docker run` 写死 GHCR 镜像 → 路径 B 不可执行（ISS-031）。
  - 当前测试提示词 §12 判据 4 仍写「两层解包」；GHCR 源 tar 布局在多处被误写为 two-stage 事实（ISS-032）。
  - ISS-029 因「关闭证据不足」处于 Reopened；plan/traceability 存在自相矛盾表述。
- 变更后：
  - **路径 A**：bootstrap/preflight 用 `sudo ... --uid 1000 --gid 1000`，卷保持 1000，构建用默认 GHCR 镜像。
  - **路径 B**：bootstrap/preflight 用 `... --uid "$(id -u)" --gid "$(id -g)"`（显式，不依赖默认值），卷保持当前 UID；构建镜像必须是本地重建的 `yp-builder:local`，通过 `IMAGE="${YP_BUILDER_IMAGE:-ghcr.io/zeek-zhao/yp-builder:wrynose-m0}"` 注入 `docker run "$IMAGE"`；GHCR 的 `wrynose-m0` 镜像在路径 B 不用于构建。
  - **测试判据**：release 归档单层解包，`STRUCT_OK mode=direct`；全文不再把「两层解包」作为当前验收要求。
  - **GHCR 源 tar 口径**：统一为「`pack.sh` 本地产出 = two-stage；GHCR 源 tar（`a8870b50…`）布局 = UNVERIFIED（未拉取验证）」；不改 `full-slices-manifest.json` 的 `layout=UNVERIFIED` 与 digest。
  - **记录收口**：新建 ISS-031/032、CHG-018、RV-016；ISS-029 按既有事实关闭（runbook §4/RV-013/HTTP Range 已 direct，真实全量重下仍属 RV-015 §5 残留，不作为关闭条件）；plan v2.16、traceability 拆分自相矛盾表述。
- **明确不改**：release 资产（8 分片 + sha256）、`expected_bytes`/`assets[].size`/`checksum_asset_sha256`、`acceptance.md` 判据结论与字节、构建配置、K-8 代码重构；不下载 11 GiB、不跑 `--mode ghcr`、不用 root 构建。

## 2. 为什么要改

- 事实依据（AI-006 §1 只读复现）：
  - uid=1234 隔离探针：默认 bootstrap → `UID_MISMATCH` exit 2；显式 `--uid 1234 --gid 1234` bootstrap/preflight 均 exit 0、属主 1234。证明脚本逻辑正确、问题在文档命令。
  - 基线 grep：runbook §3 步骤 6 裸 `preflight`；test prompt §4.2 路径 B 无 UID 参数；§12 判据 4「两层解包」；多处 GHCR two-stage 断言。
  - CHG-014 后脚本默认目标已是镜像 1000（threshold.conf），路径 B 必须显式当前 UID，不能依赖 `--build-arg` 让脚本自动识别。

## 4. 回滚方式

- 回滚命令：`git revert <本提交>`；文档命令形态恢复到 CHG-018 前。
