# YP-M0-CHG-005 · 构建并发参数下调（适配 8GB cgroup 内存限额）

| 字段 | 值 |
|---|---|
| 编号 | YP-M0-CHG-005 |
| 状态 | Approved（ISS-011 根因确认） |
| 日期 | 2026-11-25 |
| 作者 | zeek.zhao |
| 关联 | ISS-011、ISS-010、DES-005、RV-005 |
| 影响阶段 | Stage D（S5） |

## 1. 变更背景

Stage D 构建 5 次失败，ISS-011 确认根因为沙箱 cgroup `memory.max = 8GB` 下并发过载，OOM killer 杀死编译/解压子进程。当前 `BB_NUMBER_THREADS = "16"` 对 8GB 内存严重超配。

## 2. 删除的约束/常量

| 删除项 | 原值 | 所在文件 |
|---|---|---|
| `BB_NUMBER_THREADS` | `"16"` | `kas/base.yml` |

## 3. 新增/替换的约束/常量

| 新增项 | 新值 | 所在文件 | 理由 |
|---|---|---|---|
| `BB_NUMBER_THREADS` | `"4"` | `kas/base.yml` | 8GB 内存下最多 4 个并发任务 |
| `PARALLEL_MAKE` | `"-j 2"` | `kas/base.yml` | 显式限制单任务 make 并行度，最坏情况 ≤ 8 个编译子进程 |

## 4. 影响

- 只影响构建时长（预计显著变慢）与内存峰值，不影响产物内容与缓存命中语义。
- 不改变 downloads/sstate 卷布局、kas 入口与镜像契约。
- 8GB 为本构建环境实测限额（ISS-011）；未来迁移到更大内存的 CI 需按 ISS-011 §5 的预算方法重新取值。

## 5. 回滚

恢复 `BB_NUMBER_THREADS = "16"` 并删除 `PARALLEL_MAKE` 行；但回滚会复现 OOM，仅在迁移到 ≥32GB 内存环境时执行。
