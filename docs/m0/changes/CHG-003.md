## 1. 变更内容

在 `kas/base.yml` 的 `local_conf_header.base` 中新增两行：

```bitbake
# hashserv 数据库落到共享 sstate 卷，使清 build 后仍能跨构建复用（ISS-010）
BB_HASHSERVE_DB_DIR = "${SSTATE_DIR}"
# 长构建中 bitbake server 偶发通信超时，放宽等待窗口（ISS-010）
BB_SERVER_TIMEOUT = "300"
```

## 2. 为什么要改

- DES-002 §3.4 规定 `BB_HASHSERVE = "auto"`（本地 hashserv，禁止远程）。但 bitbake 首次构建警告：共享 `SSTATE_DIR` 而 hash equivalency DB 位于 build 目录时，**会阻止 sstate 复用**。S5 第二次构建命中仅 42%（976/2304），与之一致。把 DB 指向 `${SSTATE_DIR}` 可让复用跨 build 完整，符合 B-12 目标。
- 第二次构建在 `task 1338` 处 server 60s 无应答而中断，非任务失败。提高 `BB_SERVER_TIMEOUT` 到 300s 避免偶发通信抖动误判。
- 仍为本地 hashserv，不引入远程 hash-equivalence，符合约束 6 / B-07；`BB_HASHSERVE = "auto"` 不变。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | 新增 2 个本地构建变量；写入 S9 `variable-index.md`；不改变远程缓存禁令 |
| kas 配置 | 仅 `kas/base.yml` 的 `local_conf_header.base` 增加两行；repos 与 commit pin 不变 |
| 缓存复用 | 预期第二次命中率高于 42%；DL_DIR/SSTATE_DIR 挂载点不变 |
| 门禁 | S8 可校验 `BB_HASHSERVE_DB_DIR` 指向 `${SSTATE_DIR}`、无远程地址 |

## 4. 回滚方式

- 回滚命令：从 `kas/base.yml` 删除上述两行。
- 回滚后如何验证：`kas dump` 输出中不再出现 `BB_HASHSERVE_DB_DIR`/`BB_SERVER_TIMEOUT`；bitbake 重新出现"hash equivalency database is inside this particular build directory"警告。

## 5. 验证方式

```bash
# 配置落地后 dump 可见两行
docker exec kas-build bash -c 'cd /work/build-run && kas dump kas/yp.yml:kas/editions/ci.yml | grep -E "BB_HASHSERVE_DB_DIR|BB_SERVER_TIMEOUT"'
# 构建后命中率
grep -E "Sstate summary" /work/measure-logs/second-console.log
```
