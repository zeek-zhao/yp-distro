## 1. 变更内容

### 1.1 `scripts/cache/threshold.conf` 新增三个集中化常量

```bash
# S4 挂载检查契约（CHG-002 / DES-004）：与 builder 镜像 jenkins 用户对齐
JENKINS_UID=1000
JENKINS_GID=1000
# 挂载卷最小可用空间 10 GiB（preflight 只读检查，不足 exit 3）
MIN_FREE_BYTES=10737418240
```

- `JENKINS_UID/JENKINS_GID`：与 `docker/Dockerfile` 的 `ARG JENKINS_UID=1000`、`ARG JENKINS_GID=1000` 默认值一致，供 `preflight.sh`/`bootstrap.sh` 校验与对齐属主。
- `MIN_FREE_BYTES`：卷最小可用空间阈值，`preflight.sh` 用 `df -PB1` 判定。

### 1.2 定义卷标识布局契约

每卷根目录写 `.yp-volume`，含 `type=downloads|sstate`、`created_at`、`owner=yp-m0`、`schema=1`。`preflight.sh` 校验 `type` 与挂载点角色一致，缺失或不符视为未初始化/挂错卷并 `exit 1`。

### 1.3 定义 `preflight.sh` 退出码契约

`0` 可继续；`1` 其他错误（目录缺失/标识异常）；`2` 属主不符；`3` 空间不足。只读检查，禁止 chown。

## 2. 为什么要改

- 约束 8 要求「数字常量只在 `scripts/cache/threshold.conf`」。`preflight.sh` 需要 UID 与空间阈值，若散落在脚本里会形成第二处常量源，S8 门禁的「阈值唯一」检查将失效。
- DES-003 规定容器内固定 jenkins（默认 UID/GID 1000），但宿主校验脚本此前没有对应的常量来源；把 UID 契约集中化可避免脚本与镜像漂移。
- RV-010 F-03 指出旧 S7 证据被错配为 S4 判据；引入 `.yp-volume` 标识是为了让「挂错卷/空卷」可检测，不再依赖口头假设。

## 3. 影响面

| 维度 | 影响 |
|---|---|
| 变量与契约 | 新增 3 个常量与 `.yp-volume` 布局、退出码语义，写入 S9 `variable-index.md` |
| 脚本 | 新增 `scripts/preflight.sh`、`scripts/bootstrap.sh`，两者 `source threshold.conf` |
| 已有脚本 | `scripts/cache/*.sh` 与 `docker/cache-meta.json` 的现有值不变；E 阶段 `gen-meta.sh` 只取 `SLICE_MAX_BYTES`/`UPLOAD_TIMEOUT_SEC`，不受新增变量影响 |
| 镜像 | 不改 Dockerfile 与 entrypoint；默认 UID/GID 仍为 1000:1000，与新增常量一致 |
| 门禁 | S8 可加「threshold.conf 是唯一数字常量源」与「退出码语义」静态检查 |

## 4. 回滚方式

- 回滚命令：从 `threshold.conf` 删除上述三行；删除两个脚本与 `.yp-volume` 契约说明。
- 回滚后如何验证：`grep -c JENKINS_UID scripts/cache/threshold.conf` 返回 0；`ls scripts/*.sh` 无 `preflight.sh`/`bootstrap.sh`。

## 5. 验证方式

```bash
bash scripts/preflight.sh --downloads /tmp/yp-dl --sstate /tmp/yp-st
# 初始化后期望：PREFLIGHT=0
chown -R root:root /tmp/yp-dl
bash scripts/preflight.sh --downloads /tmp/yp-dl --sstate /tmp/yp-st
# 期望：BAD_OWNER_EXIT=2
```

完整验收见 DES-004 §5，真实输出写进 RV-004。
