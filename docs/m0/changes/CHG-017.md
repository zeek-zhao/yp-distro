## 1. 变更内容

- 变更前：
  - 官方顺序是 bootstrap → fetch；bootstrap 先用 `.yp-volume` 占位，随后 fetch 的 `check_target` 把「仅含 marker 的目录」判为非空 → 正常路径必须带 `--force` 才能继续（RV-014 执行偏差）。
  - `manifests/cache-full.release.json` 的 `layout=two-stage`，并把 `layout` 当作「是否分片需重组」的开关；但 GitHub release 实物顶层实测为 `downloads/ sstate/ yp-dl/ yp-st/`（`mode=direct`，RV-014），`layout` 语义混用。
  - runbook §4 / CHG-012 / RV-013 描述 release 归档为 two-stage（两层 tar），与实物 direct 矛盾。
- 变更后：
  - **release 归档就是 direct**：顶层 `yp-dl/`、`yp-st/`（空目录）、`downloads/`、`sstate/`，无 `downloads.tar` / `sstate.tar`。不迁就文档去改发布资产。
  - **官方顺序改为 fetch → bootstrap → preflight**：新机器先取缓存（目标为空，无需 `--force`），再 bootstrap 归一属主，再 preflight。正常路径不再使用 `--force`。
  - **`check_target` 防御性放宽**：目标不存在、空目录、或仅含 `.yp-volume`（无损判断，不删除 marker）视为可写；只要含任何其他条目仍 `die` 并提示 `--force` 的破坏性语义。`--force` 保留破坏性（`rm -rf` 目标卷）但提示加强；root 解包后打印 `OWNER_HINT` 提示随后 bootstrap 归一。
  - **manifest 拆语义**：`layout` 只描述归档内部布局（release 为 `direct`；`pack.sh` 本地产出已实测为 `two-stage`；GHCR 源 tar `a8870b50…` 布局 `UNVERIFIED`、未拉取验证，三者不同对象）；新增 `requires_reassembly: true` 描述「下载后需先合并分片」。`fetch-cache.sh` 重组判断改读 `requires_reassembly`，缺失时回退旧逻辑（`layout == two-stage`），保证旧 manifest 不炸；`--parts` 拒绝条件同样改读该字段；`MODE_INFO` 同时打印 `layout=` 与 `reassemble=`；新增一致性校验防止再次漂移；`unpack_archive` 保留对实际 tar 的 direct/two-stage 探测作为最后防线。
  - **更正历史记录而非篡改**：ISS-029 重开并补「关闭证据不足」；RV-013 加更正段（two-stage 只适用于 `pack.sh` 本地小样本）；RV-014 加执行偏差段（本轮用 `--force` 绕开冲突，PASS 是功能链路 PASS 非无偏差 PASS）；CHG-012 文首加更正块；deviations.md 登记偏差。

## 2. 为什么要改

- 事实依据（本轮 AI-005 §1 只读复现，未下载全量）：
  - release `cache-full.part-00` HTTP Range 前 4 KB 出现 `yp-dl/`、`downloads/.yp-volume`、`downloads/...`，**无**顶层 `downloads.tar` → release 实物为 direct。
  - 本地 `pack.sh --src downloads --src sstate --out out.tar` 的 `tar -tf` 为 `./`、`./downloads.tar`、`./sstate.tar` → `pack.sh` 产出 two-stage；无证据表明 release tar 由 `pack.sh` 产出（**UNVERIFIED**，不补命令）。
  - `fetch-cache.sh --mode unpack-only` 对仅含 `.yp-volume` 的目标报「目标非空，拒绝覆盖」并 exit 1 → 官方顺序 bootstrap→fetch 必失败。
  - `cache-full.release.json` 的 `layout=two-stage` 与实物 direct 矛盾；`manifests/full-slices-manifest.json` 源为 `a8870b50…`（GHCR 源 tar，另一对象），其布局标 `UNVERIFIED`（无拉取证据）。
- 不改发布资产：8 分片 + `cache-full.sha256` 数量不变，重组字节仍 `11153387520`，tar sha256 仍 `1c8126d4…`（acceptance v1.21 结论不动）。

## 4. 回滚方式

- 回滚命令：`git revert <本提交>`；`cache-full.release.json` 恢复 `layout=two-stage`（去掉 `requires_reassembly`），`fetch-cache.sh` 恢复以 `M_LAYOUT` 为重组开关。
- 回滚后如何验证：`bash scripts/cache/fetch-cache.sh --mode release --dry-run ...` 打印 `layout=two-stage`；`git diff` 无残留本轮文件。
